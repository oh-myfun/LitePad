>   - [ ] 搜索悬浮条中的已替换数量的提示文本要随搜索文本和文件变化，目前替换后会残留。

## ① 「仅在打开的编辑器中搜索」（`#search-open-editors`）

照 VS Code `patternInputWidget.ts` 的 `useSearchInEditorsBox`：一颗 `Codicon.book` 图标开关，
**嵌在「要包含的文件」输入框右缘**（`.search-glob-field` 相对定位 + 按钮绝对贴右）。

行为（`src/search/store.ts`）：

- `SearchQueryState.onlyOpenEditors`；打开时**不论有没有文件夹**都走内存快照那一支
  （`scanOpenDocs()`）——搜的是编辑器里的内容，未保存的改动也算数，与 VS Code
  `onlySearchInOpenEditors` 同口径。
- 范围三档：`folder` / `openDocs`（无根兜底）/ `openEditors`；计数行分别念
  「N 个文件」「N 个打开的文档」「N 个打开的编辑器」。
- 与盘上那一支的差别：不吃 include/exclude（glob 本来就是为盘上那棵树准备的）。

## ② 替换框「保留大小写」（`#search-preserve-case`）

照 VS Code `searchWidget.ts` 替换框内的 `preserveCase` 开关（`Codicon.preserveCase`）：

- 内存分支（`src/search/replace.ts`）：逐命中 `preserveCase(matched, replacement)`。
- 盘上分支：`ReplaceItem.preserveCase` → Rust `search.rs` 新增 `preserve_case()`：
  全大写 → 全大写、全小写 → 全小写、Title Case → 首字母大写其余小写，其余原样。
  正则替换走 `caps.expand` 后再对**整段展开结果**套规则（与 VS Code 的
  `expandReplaceString` + preserveCase 顺序一致）。
- Rust 新用例 `preserve_case_migrates_the_matched_word_case`：
  `bar/BAR/Bar` 三处 → `"Bar BAR bar"`；正则两处 → `"Oof OOF"`。

## ③ 结果行「清除 / 替换」按钮（照 `MenuId.SearchActionMenu`）

VS Code 的 `searchActionsRemoveReplace.ts`：文件行悬停出 action bar，`ReplaceAction` /
`ReplaceAllInFileAction` 只在替换区展开时进菜单，`RemoveAction`/`Dismiss` 常在。

落地：

- 文件行由 `<button>` 改成 `<div class="search-file" role="treeitem" tabindex="0">`，
  挂 `keydown`（Enter/Space → `row.click()`）保住键盘可达性。
- `.search-row-actions`：`display:none`，`.search-file:hover` / `:focus-within` 时出来
  （VS Code `searchview.css` 同款「悬停才显」）。里面 `replace-file`（仅替换区展开时）
  与 `dismiss`（常在）两颗 20×20 的 `.search-rowbtn`。
- store 新增 `dismissFile(path)`（过滤后重算 matches/files 并 notify）、
  `planReplaceFor(path)`（单文件计划）。`replaceFile()` 走同一个 `runReplacePlan()`，
  确认框文案「在文件中全部替换」+ 「将在 1 个文件的 N 行里替换全部匹配」。

## ④ 计数文本被遮挡（B417-4）

**根因**：`#search-count` 原来嵌在 `.search-widgets` 里、带着 `margin-top:-5px`；
「⋯」把 `.search-details`（含/排除两行）展开后，计数行的上沿压进了「要排除的文件」
输入框 —— 真机量到 count `y=179.7` vs exclude 底边 `184.7`，**盖了 5px**。

VS Code 的结构是 `.messages` 与 `.search-widgets-container` **互为兄弟**，不嵌在里面。
照此把 `#search-count` 挪成 `.search-widgets` 的兄弟（`#search-results` 之前），
CSS 的负 margin 同步收到 `-5px 12px 0 2px`（相对新的父级重新校准）。

真机复测（`.tmp/b417-probe.py`）：

| 状态 | count 顶边 | exclude 底边 | 重叠 |
| --- | --- | --- | --- |
| 展开前 vs `details` | — | — | 0 |
| 展开前 vs `more` | — | — | 0 |
| 展开后 | 185.7 | 184.7 | **0**（留 1px 缝） |

## ⑤ 预览模式禁用悬浮条替换（B417-5）

`FindBarHandle.setReplaceEnabled(on)`（`src/shell/findbar.ts`）：

- 关时：chevron `disabled` + `aria-disabled`、tip 改「预览模式下不可替换」、替换行**折起**；
- `focusReplace` 退回查找输入框；
- `src/find/findbar.ts` 的 `replaceAllowedHere()` = `viewMode !== "preview"`；
  `openFindBar` / `retargetFindBar` / 换面（`markdown.ts` 的 `applyPanelMode`）三处都调
  `syncFindBarReplaceable()` —— 三条同形路径都盖到（B355 的教训）。

## ⑥ 替换提示残留（B417-6）

上一发替换留下的计数/提示文本（如「已替换 N 处」）没有随查询或文件变化清掉：
`applyFindQuery` 第一行加 `findBar?.setStatus("")`；`retargetFindBar` 与
`openFindBar` 也各自清一次。改搜索词、改文件、再按 Ctrl+F 都不会再挂着上一份文本。
