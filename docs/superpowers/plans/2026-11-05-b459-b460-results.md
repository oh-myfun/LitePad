## B459

### ① 要什么（用户口径原样）

「任务列表在编辑模式时选中被折叠的行，选中的高亮没有覆盖所有文本，折叠行的每行开头都少覆盖了一段」
（附图为一张任务项 `- [x] 源码模式中：…`，蓝色选区色带从可见的 `- [x]` **右边**起画）。

### ② 根因（不在装饰层，在 CM6 的一把尺）

`node_modules/@codemirror/view/dist/index.js:9328-9330` —— `rectanglesForRange` 铺选区色带时，
**只读渲染出来的第一颗 `.cm-line`** 的 `paddingLeft + min(0, textIndent)`，并把这一个数套给选区里
所有非起始行。而装饰面（B401/B405 的口径）把「作者缩进 + 标记槽」全住在**行左内距**里 ⇒

- 第一颗行是列表 / 引用行 ⇒ 那个数变成 `48 + 18.9(+)`，色带左沿跑到正文左沿右边一档：
  列表行行首的方框没被盖住（用户报的那一条）；
- 同一把尺子反过来咬段落行：**普通段落开头一截字反倒被色带吃掉**（比用户报的更隐蔽，没人报过）。

也就是说这不是「色带短了」，是「按行的左内距各不相同，而 CM6 只认一个数」。

### ③ 修法：把不变量恢复成「每一行都算回正文左沿」

单一权威一颗自定义属性 `--md-lead`（这一行的标记槽有多宽），三处从它派生：

| 处 | 写什么 | 为什么 |
|---|---|---|
| `padding-left` | `calc(var(--editor-padding-x) + var(--md-lead))` | 续行的对齐仍由左内距管（`text-indent` 只管首行） |
| `text-indent`（`.md-lead-slot`） | `calc(-1 * var(--md-lead))` | 把 CM6 那颗 `paddingLeft + min(0, TI)` 按回正文左沿 |
| 占位件 `.md-mark-slot` | `inline-block`，宽 = `--md-lead`，高 0 | 负缩进把首行正文顶出去了，由它补回原位；且让 `coordsAtPos(0)` 落在槽的左沿 |

`--md-lead` 的取值：普通段落 `0px`、列表 `--md-list-marker-width/--editor-list-marker-offset`、
任务项 `--editor-list-marker-offset`、引用 `--editor-quote-bar + --editor-block-indent`、
嵌套档再 `+ 24px × (depth-1)`（仍由 `previewSets` 的行内 style 报，CSS 只派生一次）。

被折叠的行首标记由「零宽 replace」改成**一颗占位件**（`MarkSlotWidget`，`src/preview/miscWidgets.ts`）。
一颗行只发一颗槽：同一行里后面的标记（`>>` 的第二根 `>`、引用里套列表的那个 `-`）仍走零宽 `hide`，
否则两条 replace 区间交叠，`Decoration.set` 直接抛。

**否决的候选**：`::first-line { text-indent: 0 }` —— Chromium 对 `::first-line` 不吃 `text-indent`
（真机 A/B 证：首行正文跑到 52.67、排版坏了），故走占位件。

显形档（光标压住那一行）沿用 B404/B405 那套：`md-reveal-marker` 把左内距收到 marker 左沿，
本轮补一句 `text-indent: 0 !important` —— 显形时行首就是源码本身，没有槽可让位，留着负缩进会把源码
顶到正文左沿外面去。`taskClick` 的命中判据（`paddingLeft − markerOffset` = 方框左沿）一字未动。

### ⑧ 台子自己踩的四条坑（都是假红/假绿，已写进脚本注释）

1. 撤掉页面内注入的样式后 `.cm-selectionLayer` **不重画** ⇒ 每次测量前必须重发一次选区。
2. `Range.getClientRects()` 会含高度 0 的占位件矩形 ⇒ 判「首行墨迹」要 `width>0 && height>0`。
3. 「第一个直接子文本节点」判首字符是错的：`- [ ]` 住在语法高亮那颗 span 里，量到的是正文（73.28）。
   改用整行 Range 的第一颗矩形。
4. 拖选「按下在行左内距里」不等于落在 pos 0：CM6 给的是行内某个字符位（真机量到 6）⇒
   起点行的色带从正文起，判据红的是台子。改成 Ctrl+Shift+Home 造行界选区。
5. （附带）`Input.dispatchKeyEvent` 的 modifiers 位：Ctrl=2、Shift=8。

### ⑨ 已知限制

- 选区里**第一颗渲染行**是「显形档的嵌套列表行」时，CM6 那颗左沿仍是 `48 + 24×(depth-1)`：
  B405 定的「显形时左内距收到 marker 左沿」与「CM6 只认一个数」在这一档天然冲突，
  要消掉得改显形档的缩进口径（会动 B405 已验收的观感），本轮没动。
- 只读预览档同样吃这套（槽在、色带齐），但预览档不显形，所以永远走折叠档那条路。

## B460

### ① 要什么（用户口径原样）

「编辑模式中上标下标中的小数字太大且不够标准」（附图为格式工具条折叠下拉里的 `x² 上标` / `x₂ 下标` 两行）。

### ② 根因

`src/shell/toolbarMarks.ts` 里那两枚补画的「2」用了 `A`（半径 2 的弧）+ `h`，
真机骨架页量到旧上标整枚墨迹 `y 1.5..13.4`，其中那颗数字 `1.5..7.6` = **6.1 高**，
而 x 只有 4.6 高 ⇒ 数字比正文还大，读起来是「x 与 2 并排」而不是上标；
旧下标那颗更吃到 `y 14.0`（贴 16 边框）。

### ③ 改法

那颗「2」重画成 `Q` 弧 + 斜 + 底横，墨迹收到 **3.0 高（= x 的 65%，标准排版上标 ≈ 58–65%）**、
2.4 宽；上标整颗抬到 x 顶边之上（`6.5 < 7.9`）、下标整颗落到 x 底边之下（`9.5 > 8.1`），
两颗同形同宽（成对）；数字那支笔收到 1.2（与 1.4 的主笔同排不抢重量）。
两支 path 全部改成**绝对坐标 M/L/Q** —— 判据才能直接对坐标取包络（`A` 的凸出量、`h/v` 的相对位移
都得再算一遍，那判据就成「跟着画法重抄一遍」）。

### ④ 判据与鉴别力

`tests/preview-format-toolbar.test.ts` 新增一条（先看它红）：数字高 ≤ 0.7 × x 高、数字宽 ≤ 0.7 × x 高、
上标整颗在 x 顶之上 / 下标整颗在 x 底之下、住在 x 右边、墨迹不贴 16 边框、两颗尺寸一致。
`.tmp/b460-selftest.js` 用同一把尺量旧画法与新画法：**旧 FAIL=2、新 FAIL=0**（旧那版按端点量已经
是 0.717，算上弧顶是 1.32），证明判据咬得住。

### ⑤ 目视结案

`.tmp/b460-ink.html`（骨架页 + browser-use 截图，深浅底上的 16px 与 96px 两档）：旧那版那颗 2 明显比 x 大、
新那版读起来是 `x²` / `x₂`，与同排的 `underline` 补画重量齐平；页面里现量的墨迹盒：
新上标与新下标都是 `2.4..12.3 × 3.5..12.5`（完全成对），旧上标 `2.4..13.3 × 1.5..13.4`。

顺带记一条台子的坑：真机 exe 那侧 CDP 9222 这次起不来（WebView2 的浏览器进程被复用 ⇒
`--remote-debugging-port` 只在**新建**浏览器进程时生效），而「SVG 在浏览器里长什么样」是纯浏览器行为
⇒ 按既有纪律改走 `.tmp` 骨架页 + `browser-use` 截图自己看像素结案，不纠缠端口。
