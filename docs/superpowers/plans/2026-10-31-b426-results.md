## B426-1 · 第一次点击只开不落位

**根因**（这一条我早先前只说对了一半）：`jumpToLine` 里新开文档那一段是

```ts
docId = await doOpen(path);            // ← 错在这一行
```

`doOpen` 回的是新开那份**实例**的 tabId（`src/io/files.ts:246` `return tab.tabId`，号由 JS 侧
`takeInstId()` 发，`src/core/app-state.ts:293`），而下一步 `visibleInstancesOfDoc(docId)`
按 `Tab.docId` 匹配 —— `docId` 是 **Rust 侧** `alloc_id` 发的号（`src-tauri/src/commands/mod.rs:62-66`）。
**两套计数器各走各的**：号撞上就恰好能用（这就是它看起来「有时好有时坏」的原因），
撞不上就是「文件开了、没定位」，用户必须再点一次 —— 正是用户报的那一形。

**修法**（最小）：别信返回值，开完现问一次表。

```ts
if ((await doOpen(path)) === null) return;
docId = openDocIdFor(path);       // 按路径查真正的那份文档
if (docId === null) return;
```

顺带审了全仓 `doOpen` 的其余调用点（`grep`）：没有第二处把返回值当 docId 用。

**测试先行怎么做的**：`tests/search-panel.test.ts` 里 `doOpen` 那颗桩原先**回的是 docId**
（桩在替产品撒谎），所以老代码在它上面永远绿。把桩改成照产品回**实例号**（`h.openInstId`），
新用例「用户报的那一形：文件从没开过，**第一次**点就要开出来并落到命中行」立刻红；
改完落绿。B420 那两条老用例同时补上 `openInstId`，仍然绿 ⇒ 三条同形路径没被改动带坏。

## B426-2 · 节头那个数字改徽标

`rootRow` 里那一格原先只有 `.search-root-count`，颜色在自己那条规则里写死一份 ⇒ 与每族主题的
`--badge-bg / --badge-fg` 迟早漂移（B379 那一族）。改成与文件行命中数**同一颗盒**：

```ts
count.className = "search-root-count search-badge";
```

`preview.css` 里删掉 `.search-root-count` 那条自带 `color` 的规则，原地留一句「样式给 `.search-badge`，
这一格只当选择器用」的注释。`search-root-count` 这个名留着：判据与将来的样式钩子都按它认。

（`src/search/panel.ts` 的 `headed` 判据，B424 定的）⇒ 真机台必须播**两根**才打得到这一格。

### 落地分层

- **Rust**（`src-tauri/src/session/mod.rs`）：`search_exclude: String` +
  `search_use_ignore_files: Option<bool>`，都带 `#[serde(default)]`。
  ⚠️ 那颗开关必须是 `Option`：`bool` 会让老配置缺键**静默读成关着**（B392 的同一条规矩）。
  新用例 `settings_search_exclude_and_ignore_files_default`。
- **Rust**（`src-tauri/src/commands/search.rs`）：`SearchRequest` 多一格 `use_ignores`，
  有效判据是 `use_excludes && use_ignores` ⇒ 总闸关了时这一层本来就不该读；
  忽略栈空着时下面两处 `is_ignored` 自然全不命中，不用另写分支。
  新用例 `ignore_files_switch_leaves_dot_and_noise_excluded`（关掉忽略清单后
  `.gitignore` 那条不挡路，**点文件与噪声目录仍按总闸处理** —— 这两层各归各的开关）。
- **IPC**（`src/ipc/api.ts`）：`SearchArgs` 多 `useIgnoreFiles?`，缺省 `true`。
- **模型**（`src/search/store.ts`）：
  - 新的纯函数 `mergeGlobs(base, extra)`：按 `,` / 换行 切、去空、大小写不敏感去重、`", "` 拼回去
    —— **合并只在这一处**，面板那框与设置那格谁是权威不用讨论；
  - `diskArgs` 现读 `settings`：`exclude = mergeGlobs(useExcludes ? settings.search_exclude : "", query.exclude)`、
    `useIgnoreFiles = useExcludes && (settings.search_use_ignore_files ?? true)`；
  - `rerunAfterSettingsChange()`：设置改完补一发（没有查询文本时**不发** —— `runNow()` 空文本那一路
    会顺手清屏，白清一次不如不叫）。
- **视图**（`src/shell/settingsdialog.ts`）：`CATEGORIES` 多一格 `{ id: "search", label: "搜索" }`
  （关键词把「排除 / 忽略 / 忽略文件 / exclude / ignore / gitignore / node_modules」都收进来，
  否则搜「忽略」一个分类都命中不了）；新 `textareaRow()` + `fillSearchPage()` 两行。
  ⚠️ 提交点走 `change`（失焦）不走 `input`：这一项落盘连带重跑一整场搜索，
  每按一键就跑一次等于把打字变成搜索按钮。
- **样式**（`src/styles/global.css`）：`.settings-textarea` 与同页输入框同一批 token
  （`--border` / `--bg-input` / `--fg` / `--fs-ui` / `--font-ui`），`resize: vertical` —— 横向拉伸会把
  `.settings-item` 那两列网格撑破。
- **接线**（`src/prefs.ts`）：`setSearchExclude()` / `setSearchUseIgnoreFiles()`，
  同值直接返回（挪一次焦点就重写一遍设置 + 重跑一场搜索，不挡这一发就是第二个「打字触重活」），
  写完 `persistSettings()` + `rerunAfterSettingsChange()`。

## 台子这轮自己坑了三次（都记下来，别再犯）

1. **stale session**：`bc.CFG/session.json` 留着上一个 probe 的标签（`样本.md`）⇒ 它落进
   「单独打开的文件」那一节，把每一档期望名单都多算一条。改成台子自己 `write_config` 播一份只含
   `long.md` 的会话。
2. **`rect_of` 的 pick 写成箭头函数**：`find((el)=>{const e=el; return (e=>…)})` 返回的是**函数对象**
   ⇒ 恒真 ⇒ 选中 DOM 序第一个（隐藏分类页里那颗同名 switch），rect 全 0、点击甩到 (0,0)，
   于是「点 switch」「点行标题」整片假 FAIL。pick 从此只写**布尔表达式**，且 `click_sel` 见零 rect 就中止。
3. **只播一根打不到节头**：产品设计就是「单根不画那一行头」，判据要两根才成立（见上）。

## 留下的口子（照实说）

- 面板那颗总闸（B421）关掉时，**设置里的排除与忽略文件一起失效** —— 与 VS Code 一致
  （那颗闸同时置 `disregardExcludeSettings` + `disregardIgnoreFiles`），但不是「设置永远说话」。
  设置页两行说明里都把这一层交代了。
- 「忽略文件」只管 `.gitignore` / `.ignore` 这一层；点文件与 `node_modules` 那类噪声目录仍归总闸。
  两层各一颗开关，行为差异在 `search.rs` 那条新用例里钉着。
- 排除框不做校验、不报「这条模式看不懂」：语义在 Rust 的 `WalkFilter` 一处，前端再抄一份判据
  迟早分家。写坏了模式的后果是那一发搜索报「通配无效」原话（已有路径）。
- 设置改动只补一发重搜（`rerunAfterSettingsChange`），**不**保留「搜到一半改设置」的旧结果 ——
  新结果直接盖上去，与面板那颗总闸的行为同形。
