## B418-1 · 标签条右缘的渐变过渡

**根因**：`.panel-tabstrip` 是 `overflow-x: auto` 的硬裁切盒，半个标签被右缘一刀切掉，
与右侧 `.panel-ops` 之间没有任何过渡（用户要的正是「关闭按钮压住文本时那种渐隐」）。

落地（照 VS Code 的 `ScrollbarVisibility.Auto` + 自己的条带底色）：

- `src/shell/scrollbar.ts` 的 `syncOverlayScrollbar` 每次几何同步时算一条类：
  `max = scrollWidth - clientWidth`；`max > 0 && scrollLeft < max - 1` 时给
  `.panel-tabstrip-wrap` 挂 `is-overflow-right` ——「右边确实还有半截标签」才画。
  滚到最右自动摘掉（最后一个标签完整露出时不该被压暗）。
- `src/styles/global.css`：`.panel-ops` 加 `position: relative; z-index: 1`，
  伪元素 `.panel-ops::before` 从条带底色渐变到透明，`right: 100%`（贴在 ops 左缘、
  盖在标签填充之上），宽 14px，`bottom: var(--tab-stroke)` 让出头部那条 1px 线，
  `pointer-events: none`，`transition: opacity var(--transition)`。
  显隐由 `.panel-tabstrip-wrap.is-overflow-right + .panel-ops::before { opacity: 1 }` 控制。
- 层序：活动标签 `z-index` 低于 ops（ops=1），滚动条 thumb=2、拖入插入线=6 仍在最上，
  渐变不会盖住它们。

真机（`.tmp/b418-probe.py`，八标签 + 分屏）：

| 状态 | wrap 类 | 渐变 opacity |
| --- | --- | --- |
| 溢出且不在最右 | `is-overflow-right` | 1（`linear-gradient(to right, transparent, rgb(25,26,27))`） |
| 滚到最右 | 无 | 0 |
| 滚回左端 | `is-overflow-right` | 1 |

## B419-1 · 搜索结果视图：徽标 / 命中行动作 / 计数文案

### ① 命中数 = VS Code count badge

- `src/search/panel.ts` 文件行末尾 `<span class="search-badge">N</span>`（截断时带 `…`）。
- `src/styles/preview.css`：几何照 `countBadge.css` —— 18px 高、`border-radius: 11px`、
  左右 5px、`font-size: var(--fs-meta)`（11px 档，不写裸数值，B337 契约）、
  `font-variant-numeric: tabular-nums`、`margin-left: auto` 推到行尾。
- 配色取 `badge.background/foreground` 两族 token：`--badge-bg/--badge-fg`，
  `src/styles/global.css` 按 10 套主题各写一份（2026 / modern / plus+classic / hc 的
  dark+light 共 8 条 + `:root` 默认）。
- **动作键出现时徽标让位**（VS Code `searchview.css` 同款）：
  `.search-file:hover/:focus-within > .search-badge { display: none }`，
  同一时刻 `.search-row-actions` 从 `none` 变可见。

### ② 每条命中也有「替换 / 清除」

- 命中行从 `<button>` 改成 `div.search-line[role=treeitem][tabindex=0]`（button 套 button
  不合法）；键盘 Enter / 空格在 `setupSearch` 的 keydown 里补回「点这一行」。
- 动作键按 VS Code `searchActionsRemoveReplace.ts` 的 when：
  - `replace-match`（替换这一处）只在替换行摊开时出现（`ReplaceActiveKey`）；
  - `dismiss-match`（清除这一条）常驻。
- store 新增 `dismissMatch(path, line, column)`：只摘命中行与列对得上的那一条，
  空组自动消失，`matches/files` 重算（不动 `collapsed`）。
- 单处替换（`src/search/replace.ts` 的 `replaceSingleMatch`）：
  - **开在标签里**的文档：按 `line + column`（1 起算的**字符**列，与 `SearchMatch`
    同口径）在 `findMatches` 里认准那一处，改内存、置脏、不写盘；
  - **只在盘上**的：`ReplaceItem` 新增 `line/column`（`src/ipc/api.ts` + Rust
    `ReplaceItem` 的 `Option<u32>`），Rust 的 `replace_literal/replace_regex` 走到
    **按行列只动那一处**的分支；只给一半位置 = 没有语义，按全换处理（`target_of` 返回 None）。
- 用例：`tests/search-panel.test.ts` 新增 5 条（徽标/让位 CSS、命中行两颗键、
  清除一条、开着的文档单处替换、盘上单处替换带 line/column）；Rust 新增
  `replace_one_match_only_touches_the_given_position`（literal / regex / 半截位置）。

### ③ 计数文案简化

`src/search/store.ts` 的 `summaryMessage()` 统一成 VS Code `"{0} results in {1} files"`
的中文形：**`在 N 个文件中找到 M 个结果`**，不再按范围换「个打开的文档 / 个打开的编辑器」
那两句（B417 结果文档里那三档说法自本版作废；范围由那颗开关与范围说明行表达）。
撞上限仍是同句 + 「（已达 N 条上限，这不是全部）」。

真机（`.tmp/b419-probe.py`）：`在 2 个文件中找到 4 个结果`；a.md 徽标 `3`；
悬停文件行时徽标 `display:none`、动作键出现；替换行收起时命中行无替换键、清除键在。

## B419-2 · 禁用替换时展开键的禁用观感

`src/styles/global.css` 在 `.find-chevron:hover` 之后补：

```css
.find-chevron:disabled,
.find-chevron:disabled:hover { background: transparent; color: var(--fg-muted);
  opacity: 0.4; cursor: default; }
```

`:disabled:hover` 必须单列：与 `.find-chevron:hover` 同特异度，靠后写才盖得住。
其实仍是 B417 的 `setReplaceEnabled(false)` 在压 `disabled`，这里只补「看得出来按不动」。

真机：预览档打开查找条，`disabled=true`、`opacity=0.4`、`cursor=default`、替换行收起。

## B419-3 · 单次替换的计数累计

`src/find/findbar.ts` 新增模块级 `replacedCount`：

- `replaceCurrent`：每成功换一处 `+1`，状态行念「已替换 N 处」（连点 1 → 2 → 3…）；
- `replaceAllInScope`：按这一发换掉的处数累加（与单次同一个口径）；
- **清零只有一个口** `clearReplaceStatus()`：`applyFindQuery`（查找内容 / 选项 /
  换文档 / 重开 / 换搜索范围）与新增的 `onReplaceTextChange`（替换串输入框 input）
  都走它 —— 上一发说的已经不是这一批匹配了。

真机：连点两次替换键 →「已替换 1 处」→「已替换 2 处」；改查找内容后状态行 `hidden`。

## B419-4 · 「在选区中查找」随选区变化刷新

原来的冻结锚点只在**开关打开 / 重开 / 换文档**时播种，用户换选区后结果仍是旧范围的。

- `src/main.ts` 的 `handleUpdate`：`update.selectionSet && 活动面板` 那一格里，除了
  `refreshTocAtCursor` 再补 `refreshFindOnSelectionChange()`（与大纲同一处上报）。
- `src/find/findbar.ts` 的 `refreshFindOnSelectionChange()`：
  查找栏开着 + 查找内容非空 + 「在选区中查找」开着时，重取锚点并 `applyFindQuery`。
  - **空选区不动**（点一下正文 / 跳到某行不是「换了个更小的范围」；清掉锚点会让结果
    突然扩回全文、与亮着的开关对不上 —— B304 那类「显示与行为两套口径」）；
  - **自己的步进 / 单次替换**也会改选区（设成命中本身），新增 `dispatchOwn()`
    在这两处发事务时挂 `suppressSelectionRefresh` 闸 —— 否则第二次按「下一个」范围就
    塌成那一个命中（B76 那条老病会以新形式回来）。
- `tests/findbar.test.ts` 的 B76 契约随之改写：实时选区**只允许在「重取锚点」两处**读
  （`seedFindSelectionAnchor` + `refreshFindOnSelectionChange`），范围判定绝不实时读。
- 用例：`tests/findbar-app.test.ts` 新增 3 条（换查找内容清零 / 换替换内容清零 /
  换文档清零）+ 2 条选区用例（换选区 1/2 → 1/4、空选区保持；步进不塌缩 1/2 → 2/2 → 1/2）。

真机：选区只覆盖无命中行时计数「无匹配」；Shift+点扩到含两处命中 → 「1 / 2」；
点一下正文（空选区）仍是「1 / 2」（全文是 1 / 3）。

## 本轮踩到的坑（写给后来人）

1. **真机台的 `folder_root`**：`bc.write_config()` 只写台子的公共夹具根；探针自己的
   目录必须事后改 `settings.json`，否则搜的是整个 `b352-fixtures`（真机照出
   「9 个文件 / 12 个结果」）。
2. **`inline-flex` 的计算值**：`.search-row-actions` 是 flex 容器（`.search-file`）的子项，
   `getComputedStyle().display` 会 blockify 成 `flex`；判据只认「不是 none」。
3. **字阶契约**：徽标 11px 必须写 `var(--fs-meta)`，裸 `font-size: 11px` 会被
   `tests/type-scale.test.ts` 判红。
4. **B417 那三档计数文案**属于上一版的口径；本版统一后，只改了行为与测试，
   B417 结果文档保留原样作历史记录（本文件已注明作废）。
