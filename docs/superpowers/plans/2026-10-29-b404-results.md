# B404 · 编辑模式：语言下拉 / 光标行显形 / 未勾选不划

用户（2026-10-29）：

> 优化编辑模式中样式：1、代码段下拉列表组件；2、光标在任务项时前面的勾选框变回代码（引用块好像有同样问题），光标不在对应任务项时仍然要可以直接点击切换勾选状态；3、任务项未勾选时不用删除线；

## 一、代码块语言下拉：换回应用自己的下拉

原生 `<select>` 的**展开列表是系统画的**（WebView2 里白底黑字），和应用 `.popup-menu`
那套菜单完全两个世界。改用 B108 的 `src/shell/dropdown.ts#createDropdown`：

- 触发器 = `button.dropdown-trigger.md-codeblock-lang`，列表 = `.popup-menu.dropdown-list`；
- 只读档照旧：下拉藏起来、静态语言标签在场；
- `updateDOM`：只换语言（代码没动）时**不重写代码**（保住光标），但 `<pre data-lang>` 与
  Shiki 高亮按新语言重来 —— 以前那一路没写，改完语言配色还停在上一种；
- 下拉根节点 mousedown 不让块级编辑层抢焦点，keydown 也不漏给 CM6（Enter 是选中不是换行）。

真机抓到一条**通用坑**：`positionList()` 只按视口算「上面还放得下」，而本应用的自建标题栏
是 webview 里的一层 DOM —— 代码块在文档中段时，列表会被顶到标题栏背后去。可用区上边界
改成 `#title-bar` 下沿 + 8px。

## 二、光标行：勾选框 / 引用竖线让位给源码

原来 `TaskMarker` 与 `QuoteMark` 用的是 `NEVER_REVEAL`（列表符号那一档「永不显形」），
所以光标压上去也只看到 CSS 画的方框 / 竖线。现在：

- 两者的 hide 装饰带**所属行范围**的 reveal 窗口 ⇒ 光标落在这一行时 `[ ]`/`[x]`、`>` 显形；
- 伪元素没法被选区过滤 ⇒ `visible` 集里补一颗行类 `md-reveal-marker`（只在「可写 + 光标行
  是任务行/引用行」时给），CSS 用它收掉 `::before/::after` 与标记槽左内距；
- `taskClick`：**可写档里光标就在这一行**时不再接管点击（这一下是放光标/选字）；预览档
  （只读，标记永远折着）与其它行照旧「点一下翻一行」。

## 三、未勾选不带删除线

现状取证：混合任务项（无序/有序/星号/加号/嵌套/续行/引用内/带行内构造）逐行量
`className + text-decoration-line`，**未勾选一律 `none`**；点勾两次（勾上→取消）也确认
`md-task-done` 跟 `line-through` 一起消失。本批把它钉成契约：

- CSS：删除线只挂在 `.md-task-done`，基态任务行不许出现 `line-through`；
- 真机台 T-05：点回未勾后 `td == none`。
