# B456 结果 · 图表卡片不许撑宽编辑区 + 双击复位视图

日期：2026-11-03 · 版本：**v0.26.0**（沿用 B455 那一档，本轮不重复推）· 状态：**未提交、未推送、未发版**

## 用户原话

> 支持图表空白区域双击进行复位。好像有图表渲染会导致区域卡片尺寸异常（宽度超出编辑区，右边三键看不到，且连带同屏中的卡片都出现宽度异常）

拆成两格：**#367** 卡片不许把整块内容层撑宽（右上角三颗键因此跑出窗口），**#368** 图里双击 = 复位视图。

## B456-1 · 谁把卡片顶宽

真机取证（`.tmp/b456-wide.md` + `.tmp/b456-width-probe.py`）量到的形状：

| 量的那把尺 | 修前 | 说明 |
|---|---|---|
| `.cm-content` 宽 vs `.cm-scroller` 可视宽 | **3077 / 3371 vs 1161** | 内容层整块被撑宽，不是某一张卡片的事 |
| 卡片自己的宽 | 跟着 `content` 一起变宽 | 卡片是 `display:block`，父层多宽它就多宽 |
| 三颗键的右边缘 vs 窗口宽 | 3027 / 3321 vs 1180 | 「右边三键看不到」= 键钉在卡片右沿，卡片飘出窗口 |
| 伸出卡片右边缘的孩子 | `[]`（空） | **排除**了「某个渲染器画得比格子宽」这一层 |

`over: []` 是定性的那一发：凶手不是「图伸出卡片」，而是**块 widget 的固有宽度（max-content）参与了 `.cm-content` 的宽度计算**。CodeMirror 6 的内容层按 max-content 取宽，所以一张宽 mermaid / 40 类的 ECharts 会把整块内容层撑起来，同屏每一张卡片跟着变宽。

原来那条 `.md-diagram-widget .md-diagram svg { max-width: 100% }` 顶不住 —— 那个 `100%` 量的正是**已经被撑宽的这张卡片**。

修法：给块 widget 的根加 `contain: inline-size`（[src/preview/preview.css:944](../../../src/preview/preview.css)）—— 尺寸隔离让这一格的**固有宽度与内容脱钩**（内在贡献按「没有内容」算），卡片宽度重新由 `.cm-content` 给；宽出去的图由卡片那道 `overflow: hidden` 收住，看全貌交给 B455 那层平移缩放。

顺带被这一格治到的：ECharts / 五线谱动笔时量的是「最近一颗真在文档上的祖先」的 `clientWidth`（`cardContentWidth`），修前量到的是 3037 那颗假宽 ⇒ 画出来就是 3037px 的一张图；现在按真实编辑区宽渲染。

判据：jsdom 不做级联 ⇒ 这条只能钉 **CSS 契约**（`contain: inline-size` 落在那条规则里）+ **真机几何**（内容层回到可视宽、三颗键回到窗口内）。见 [tests/preview-diagram-viewport.test.ts](../../../tests/preview-diagram-viewport.test.ts) 的「B456-1」。

### 对照量出来的同类遗漏：宽表格同一条病

台子顺手量了两格**不是图种**的块 widget 当对照（夹具里隔开一百行正文，免得两格同屏归不到具体某一格）：

| 对照 | 修前 | 修后 |
|---|---|---|
| 30 列宽表格 | `.cm-content` 被撑到 **1294** vs 可视 1161 | 1161 = 可视宽；表格 1250 宽落在 `.md-table-body` 的 `overflow-x: auto` 里横滚 |
| 一行 400 字的代码块 | 1161（**没有**这个病） | 同；`pre{width:0}` 早就把固有宽度脱了钩 |

⇒ 表格那一格补同一条 `contain: inline-size`（[src/preview/preview.css:721](../../../src/preview/preview.css)）。代码块不动 —— 它已经是对的，那条 `pre{width:0; overflow-x:auto}` 就是同一件事的旧写法。

## B456-2 · 双击复位

[src/markdown/diagramViewport.ts:192](../../../src/markdown/diagramViewport.ts)：卡片收到 `dblclick` ⇒ 视图直接回到 `IDLE_VIEW`（1:1、位移归零），并顺手 `preventDefault()` 掐掉「双击选词」；右上角那三颗键那一格除外（在键上双击不许变成回零）。复位同时发一颗 `DIAGRAM_RESET_EVENT`（`md-diagram-reset`）冒泡出去，让编辑入口那边知道。

**这一格真正的坑不是复位本身，是它和「点图进编辑」抢同一发手势。** 源码框开在图的**上方**：第一发点击如果当场把源码框浮出来，图就被往下顶，第二发落到源码框里（还顺手选个词）—— 双击根本轮不到复位。所以 [src/preview/richWidgets.ts](../../../src/preview/richWidgets.ts) 把「点了图」到「浮出源码框」之间延后一拍（`TAP_SETTLE_MS = 200`），延后期里收到 `md-diagram-reset` 就整发取消：

- 纯点击 → 200ms 后浮源码框（手感上仍是「点一下就改」）；
- 双击 → 第二发之前那拍没到 ⇒ 图没被顶走，复位成立，源码框不浮；
- 用户本来就在改这张图（`openPending === undefined`）⇒ 复位视图不许抢走已经开着的源码框。

判据两侧都钉了：变换层（[tests/preview-diagram-viewport.test.ts](../../../tests/preview-diagram-viewport.test.ts) 的「B456-2」两条，含「先放大平移过」的前置断言，免得拿没动过的图自证）与编辑入口（[tests/preview-face-mermaid-edit.test.ts](../../../tests/preview-face-mermaid-edit.test.ts)：松手当场不许开、过了那一拍才开、双击过后整发不开；旧的「拖过阈值/按按键不进编辑」两条也补了 `await tick(250)` —— 延后一拍会让**当场判「没开」失去鉴别力**）。

## 台子这一轮的三处自伤（记下来免得再踩）

1. **graphviz 那条红是夹具的锅**：`a1[label="…"] -> a2[label="…"]` 在 dot 里就是语法错误（`syntax error in line 1 near '->'`），产品按设计退回源码那一格。改成「先声明节点、再连边」后画得出来 —— 拿 node 直接跑 `Graphviz.load().layout()` 一次定案，不猜。
2. **`focus()` 红的时候必须报出停在哪一步**（滚不到 / 卡片整块没换 / 换了但 canvas 空 / 画失败退回源码），否则一条红只能得出「图没画出来」，产品与台子分不开。
3. **对照两格必须隔开**：CM6 只挂视口内的块 widget，壬/癸 同屏时 `contentW=1294` 归不到具体哪一格；中间垫一百行正文之后才量出「表格有病、代码块没有」。

## 这一改的可见后果（不是 bug，先说清楚）

1. **宽图现在缩到卡片宽**（`max-width:100%` 量的终于是别人家的宽度了）：十四节点的 mermaid 一屏排得下但字很小 ⇒ 看细节交给 B455 那层滚轮/按键；这是「卡片不许撑宽整块内容层」的直接对价。
2. **宽表格改成格内横滚**（原来整块内容层跟着变宽）：30 列的表在窄格里列宽被压到换行，横向滚动条落在卡片内。
3. **点图进编辑慢了 200ms**（延后一拍）：手感是「点一下，稍等一下源码框浮上来」；换来的是双击能复位视图。
