## B453-1 · `NotSupportedError: Could not resolve relative length`

**真凶**：markmap 的 d3-zoom 没被接管 extent 时，默认那颗 `defaultExtent` 去读 `svg.width.baseVal.value`。Chromium 对**脱离文档**的 `<svg>` 上「量不出的相对长度」（`width="100%"`）直接抛这一发；`viewBox` 存在时走的是另一条分支，量得出，不炸。

真浏览器 A/B（`.tmp/b453-svglength.html` + `.tmp/b453-mm-repro.html`，本地 esbuild 捆真 markmap）：

| `<svg>` 状态 | 读 `baseVal.value` | 结果 |
|---|---|---|
| 在文档里 | 量得出 | 正常 |
| 脱离文档、无 `viewBox` | 抛 | 用户那条 `NotSupportedError` 原文 |
| 脱离文档、有 `viewBox` | 走 viewBox 分支 | 正常 |
| 创建时脱离、250ms 后 append | 抛（已经晚了） | `prod` 臂实测：生产路径进不到这一形 |

LitePad 什么时候会脱离文档？这块 DOM 是 CM6 的 widget：`enhanceMarkdown` 半路放弃（`isEnhanceStale` 那一发 `return`，`host` 永远不挂上去）、以及 B398「按视口解析」滚动时不停摘旧层。`Markmap.create(...).then(fit)` 里 `fit()` 同步读 extent ⇒ 谁撞上谁炸，日志里那条 `boot error` 就是它。

**修法**：extent 自己给（[src/markdown/diagrams.ts](../../../src/markdown/diagrams.ts) 脑图臂）。`getBoundingClientRect()` 两种状态都量得出来（脱离文档是 0，不抛），所以拿它当 extent 的尺子。

**判据三层**：① jsdom 契约（给 `svg.width/height` 装会抛的 getter，判 extent 回调只量矩形）；② 真浏览器台（改前抛原文、改后不抛、正常路径照样画图）；③ 真机（滚遍五类图之后没有红条 = 没有未捕获错误）。

## B453-2 · 出错时不许挡标题栏

两份副本（`index.html` 里那段前置脚本 + `src/main.ts` 的 `showFatalError`）原来是 `position:fixed; top:0; left:0` 的整幅红条 ⇒ 盖掉标题栏、标签带、工具条。改成**右下角可关卡片**：`right:12px; bottom:12px; max-width:min(520px,60vw); max-height:45vh`，右上角一颗 `×`（关掉的只是提示，错误仍写进日志）。

那颗键用 `aria-label` 不用 `title` —— 全应用「不许再写原生 title」那条守卫（`tests/tooltip-classes.test.ts`）把它抓了一次，是本轮的自伤，不是历史遗留。

真机量到：卡片 `top=709` vs 标题栏 `bottom=34`，宽 410 / 视口 1180；关掉之后再冒新错误仍能重新露出来。

## B454 · 编辑时预览与源码同时显示

### ① 显隐：删两条「编辑态把渲染结果收掉」

`preview.css` 里 `.md-diagram-widget.md-block--editing .md-diagram-inner{display:none}` 与 `.md-block--editing > .md-metadata-preview / > .md-html-preview{display:none}` 一起删掉。脑图的源码就是一串 `- 项目`，图一藏等于盲改 —— 这就是「脑图未支持编辑」的第一层。公式块本来就没有这类规则（B435 那轮就是按「源码在上、渲染在下」画的），五类图与 metadata / HTML 现在跟它同一条口径。

### ② 实时重画：`onInput` + 400ms 防抖

InkNote `mermaid.ts:94` 同一把尺。差别只在 PlantUML：`onInput` 里直接 `return`，退出编辑那一发才发请求（`onEditingChange(false)` 兜底补上打字期间被防抖吃掉的那几发，以源码框里的最终文本为准）。

### ③ 别漏 ResizeObserver

实时重画之后同一格每 400ms 换一个 Markmap，而每一发都自带一颗观察自己那些 `foreignObject` 的 ResizeObserver ⇒ 不释放就是「每停一下打字漏一个」。`liveMarkmaps: WeakMap<HTMLElement, () => void>` 记每格当前活着的那一发，重画前先叫它的 `destroy()`。

### ④ B454-2 · 脑图点不动的真凶（真机才抓得到）

五类图逐一点一遍：**只有脑图点了没反应**。markmap-view 给那颗 `<svg>` 装了 d3-zoom，它 mousedown 里的 `noevent()` = `preventDefault()` + `stopImmediatePropagation()` ⇒ 挂在 wrap 上的**冒泡档**监听器根本收不到。

**修法**：那颗监听器改捕获相（`addEventListener("mousedown", …, true)`）。判据在 `tests/preview-face-mermaid-edit.test.ts`：往图里塞一颗自己 `stopImmediatePropagation` 的 `<svg>`，点它必须进编辑态 —— 变异核对过（改回冒泡档当场红）。

## 台子这轮自伤的三处（都是假红，记下来别再踩）

1. **判据把 `innerText` 截到 120 字符**：markmap / mermaid 往图里注一整段 `<style>`，120 个字符全是 CSS 变量，marker 永远「找不到」。⇒ marker 判定在页面里现算布尔，别拿截断后的字符串回传。
2. **手工 `contentDOM.append(widget)`**：CM6 的 ContentObserver 把正文层里不认识的孩子摘掉，整块当场脱离文档，判据静默变红（连带把 PlantUML 那条也拖红）。要 `findFromDOM` 生效就挂 `view.dom`（`.cm-editor` 那一层）。
3. **图还没画完就取落点**：懒 import + wasm 没落地时那一格高度是 0，`elementFromPoint` 打到别的行上 ⇒ 派发目标根本不在图里。⇒ 先问 `innerHasInk && pointInside` 再点。

## 已知边界

- PlantUML 深色档仍是服务器给的白底卡片（用户：保持现状）。
- 「创建时脱离文档、事后才 append」那一形会把 markmap 留在 `scale(0)`；生产路径进不到（enhance 在同一批微任务里 append，`prod` 臂实测过），不再加兜底。
- CM6 widget 被销毁时 Markmap 实例仍会漏（只堵住了「同一格重复重画」这一类，也是实时重画新引入的那一类）。
