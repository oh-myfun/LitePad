## 病灶先量出来（合成到各档 `--bg` 上算 RGB 距离）

「区分不明显」不是一个感觉，2026 族（默认）里有三对真的塌在一起：

| 一对 | 深色档 | 浅色档 |
|------|--------|--------|
| 当前项 vs 其余命中 | **Δ8.8**（`#27678290` vs `#27678280`，只差一档 alpha） | Δ44.7 |
| 其余命中 vs 选中同词的自动出现 | **Δ17.6** | **Δ5.9**（`#0069CC1A` vs `#0069CC15`） |
| 当前项 vs 选区本身 | Δ42.3 | **Δ0.0**（两者都是 `#0069CC40` —— 完全同一个色） |
| （参照）选区 vs 自动出现 | Δ68.6 | Δ50.6 |

同一色相只切 alpha，是把四件事（选区 / 自动出现 / 其余命中 / 当前项）挤在同一条淡蓝带上，
屏幕上看就是「一片蓝，谁也不突出」。另外一层 LitePad **从来没画过**：
`editor.findRangeHighlightBackground` —— 「在选区中查找」只把范围外的命中筛掉了，
却没告诉用户「这一片才是搜索范围」。

## 切片 1 · token：补上缺的那一层，2026 族换色相（`src/styles/global.css`）

八个变体块各加两颗：`--find-range` / `--find-range-border`（与既有
`--find-match` / `--find-match-other` / `--find-match-border` / `--find-match-other-border`
同段），**值全部写在既有的变体块里**，没有另起一段追加的 `:root`
（ house 的判据 `themeBlock()` 只认每个 mode 的第一块，追加段会跟头一份漂移）。

- 范围带逐族照抄 VS Code：2026 深 `#ffffff13`、浅 `#00000015`（`2026-*.json` 的显式值）；
  modern / plus / classic 落注册默认 `#3a3d4166` / `#b4b4b44d`；
  HC 两档 VS Code 把底色注册成 **null** ⇒ 底色 `transparent`，只留一圈
  `transparent(activeContrastBorder, 0.4)` 算出来的边（深 `#f3851866`、浅 `#006bbd66`）。
- 两处**故意的偏离**（用户要的是「明显一点」，纯照抄给不了），已在注释里点名：
  1. 2026 族的「其余命中」从 `#27678280` / `#0069CC1A` 换成 **橙 `#ea5c0055`** ——
     这不是我发明的颜色，它就是 VS Code 对 `findMatchHighlightBackground` 的注册默认值，
     modern / plus / classic 各族本来用的就是它 ⇒ 换过去是「把 2026 拉回其余各族同款」，
     同时让命中与淡蓝自动出现**跨色相**，不再同族比 alpha。
  2. 当前项在非 HC 档也画一圈描边：结构照 `.currentFindMatch` 的 `border: 2px solid
     findMatchBorder`，只是该色在 VS Code 非 HC 注册成 null 所以它不画。这里取该族
     `focusBorder`（`--accent`）⇒ 当前项 / 其余命中 / 自动出现从此三档各有各的形状。
- 自动出现（`.cm-selectionMatch` = `editor.selectionHighlightBackground`）**一个字节没动**：
  它本来就忠实于 VS Code；把命中挪开之后，「自动高亮 vs 命中」自然分开了，不需要动它。

## 切片 2 · 装饰：`restrict` 那几行画整行带（`src/editor/find.ts`）

- 新导出的纯函数 `scopeLineStarts(doc, restrict)`：把选区经过的行的**行首**逐个吐出来。
  终点正好落在某行行首时那一行不算（VS Code 对 `endColumn === 1` 同一处理，
  否则选区末尾会把下一行也涂上）；`restrict` 为 null、空选区、越界都回空表。
- `.cm-find-range` 画在 `.cm-line` 上（整行），不是画在选中那截文字上 —— 带的语义是「范围」，
  带里带外的命中都得看得见。
- ⚠️ **两个 `StateField`**，不是一个：行装饰与**同一行行首**起手的区间装饰（命中）挤进同一个
  `Decoration.set` 会撞 CM6 的交叠检查（`previewSets.ts` 那边踩过、注释里写着）。
  `EditorView.decorations` 是多值 facet，各供一份就行。
- 重算的触发口：`tr.docChanged` 或 `setFindQuery`（改词、改范围、关掉查找栏都走后者），
  其它事务原样返回旧表 ⇒ 不带范围时开销为零。
- CSS 用 `background-image: linear-gradient(...)` 画带，**不用定位伪元素**：伪元素带
  position 会画在文字之上（定位子元素在普通流内容之后绘制），而 `background-image` 天然叠在
  `background-color` 之上、文字之下，零布局影响 ⇒ 当前行底色与带子能同时看见，谁也不吃掉谁。
  HC 那一圈走 `box-shadow: inset`，同样不吃布局。

## 切片 3 · 用例（`tests/highlight-ladder.test.ts`，26 例）

- **带的落点**（jsdom 起真 `EditorView`）：夹具 `"甲甲\n针一\n针二\n针三\n乙乙"` +
  `restrict {from:4,to:10}` ⇒ 带恰好 `行4/行5/行6`，且与 `.cm-find-match` **共存**
  （两颗 facet 各供一份，不互相顶掉）；清空范围后一行不剩。
- **阶梯这把尺**：`tokenOf()` 自己实现「基座 < `[data-theme]` < `[data-theme][data-theme-family]`、
  后者赢、`var()` 展开一层」的级联（因为判的是最终落在屏上的合成色，不是源码里那行），
  再把每层 alpha 合到该变体的 `--bg` 上算距离。阈值：三对底色两两 **≥40**、带 vs 底 **≥20**。
- HC 两档单独判：底色档全透明（VS Code 注册成 null），分档靠描边不靠色。
- 取值来源钉死：2026 有显式值、其余族落注册默认（谁抄错了当场红）。
- 两条反向自检：把旧那两档（同色相 `#0069cc1a`）喂同一把尺 ⇒ 必须判成「分不开」，
  证明这把尺有鉴别力，不是恒绿；以及带被改成定位伪元素时必须红。
- 跟着改口的：`tests/theme-vscode.test.ts`（EDITOR 深/浅两张表新增两 token、
  `FAMILY_KEYS` / `FAMILY_KEYS_LIGHT` 各加 `--find-range` 行、
  「边框」判据从 `outline-color:` 换成 `outline: 2px solid var(--find-match-border)`、
  「每族都得定义」名单加两颗）。
