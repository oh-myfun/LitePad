## B455-1 · 依赖与图种注册表

新增依赖：`echarts ^6.1.0`、`abcjs ^6.7.2`、`wavedrom ^3.8.0`、`json5 ^2.2.3`（ECharts / WaveJSON 的无引号写法）。全部**懒 import**，首屏不为它们付体积。

`DiagramKind` 从五类扩到八类：`mermaid / mindmap / graphviz / flowchart / plantuml / echarts / abc / wavedrom`。注册表在 [src/markdown/diagrams.ts](../../../src/markdown/diagrams.ts)，`RENDERERS` 是一颗 `Partial<Record<DiagramKind, DiagramRenderer>>`。

**在册没接线 = 静默退回源码块**，这类漏最不好查，所以补了一条静态完整性判据（`tests/markdown-diagrams.test.ts`）：从源码里读 `DiagramKind` 的联合类型与 `RENDERERS` 的键，两边做差必须为空；并自带变异核对（内存里抹掉一支渲染器，判据必须红）。同一发把旧的「还没接线的图种 ⇒ reject」那一条改用伪造的 `"vega"` 当靶子 —— 它原来拿 `wavedrom` 当"没接线"的例子，接线之后那条测试就成了假绿。

## B455-2 · ECharts（[src/markdown/diagrams.ts:307](../../../src/markdown/diagrams.ts#L307)）

- **SVG renderer**：canvas 在暗档糊、导出/打印要矢量。
- **尺寸显式给**：这一刻容器多半还在文档外（CM6 widget），让 echarts 自己去量就量到 0 宽 ⇒ 真机是一张挤在左上角的小图。宽度扣掉卡片左右各 20px 内边距，那颗 `CARD_PADDING_X = 20` 与 `preview.css` 同源，有一条判据钉着（谁改 CSS 不改这里就红）。
- **默认档全从 token 派生**：`backgroundColor: transparent` + 系列色走 `seriesPalette()`（与脑图同一颗表，B377 红线：不许有第二份色表）+ `textStyle.color = --md-fg`；作者写过的顶层键整个让位。
- 同一格实时重画之前先 `dispose()` 上一发（`liveCharts: WeakMap`），不然每 400ms 漏一颗实例。
- 围栏内容用 JSON5 吃：`{ series: [ { type: 'bar', data: [1,2], } ] }` 这种无引号 + 尾逗号的惯例写法要认；两形（原样 / 补外层花括号）都不行才 reject。

## B455-3 · 五线谱（[src/markdown/diagrams.ts:338](../../../src/markdown/diagrams.ts#L338)）

`abcjs.renderAbc` 画 SVG。abcjs 对不合法的 ABC **不抛异常**，只是画不出谱线 ⇒ 空框比源码更难懂，所以量一颗"有没有谱线"再决定：画不出就 reject，调用方退回源码块（与其余图种同口径）。

## B455-4 · WaveDrom（[src/markdown/diagrams.ts:362](../../../src/markdown/diagrams.ts#L362)）

**每一发渲染关进自己的 shadow root**：

```ts
const tree = box.attachShadow({ mode: "open" });
wavedrom.renderWaveElement(uid, source, tree, wavedrom.waveSkin);
```

库只走 `appendChild` / `innerHTML`，ShadowRoot 两种都吃（`src/vite-env.d.ts` 里那颗 ambient 声明的 `outputElement` 因此写成 `Element | ShadowRoot`）。这一形一次解决四件事：皮肤那张 28 条的 CSS 不外溢、它那 ~238 颗写死的 DOM id 不撞车、两块波形各用各的、选择器**逐字不动**。

取色覆盖改成**树内再挂一条 `<style>`**（排在皮肤之后 ⇒ 同特异度后者胜），见 [src/markdown/diagrams.ts:190](../../../src/markdown/diagrams.ts#L190) 的 `WAVEDROM_INK`，颜色全写 `var(--md-*)`（自定义属性穿得进 shadow 树）。`preview.css` 里那些 `.md-diagram--wavedrom text{…}` 永远够不到树内 ⇒ 是死 CSS，删了。

裸 body（`signal: [...]`，少外层花括号）也认 —— wavedrom 编辑器里就常这么写。既没有 `signal` 也没有 `assign` / `reg` ⇒ reject。

## B455-5 · 统一变换层（[src/markdown/diagramViewport.ts](../../../src/markdown/diagramViewport.ts)）

一颗 `DiagramView { x, y, scale }`，`translate(x,y) scale(k)` 作用在 `.md-diagram-canvas` 上，原点钉在 canvas 自己的左上角（缩放锚点算的就是"指针相对这一格左上角"）。倍率夹在 `0.2 – 8`，**顶到上下限整发不动**（连偏移也不动，否则图会在按到底之后一路飘）。

- 滚轮一档 `1.15×`（贴滚轮节奏，连滚不闪），按键一档 `1.3×`（有意按的就给大一点，两颗键能拉开明显一档）。
- 右上角三颗键 `codicon-zoom-in / zoom-out / screen-normal`，挂在**卡片**上而不是 canvas 上（渲染器会反复清空 canvas，mermaid 甚至直接 `innerHTML =`）；锚 = 可见区域中心（用键盘点的人没有"光标落在哪"这回事）。刻意不做"悬停才出现"—— 图放大了就得一直有路可退。
- 拖拽：`mousedown` 后位移过 `DRAG_THRESHOLD_PX = 4` 才算平移（加 `md-diagram--panning` ⇒ 光标 `grabbing`），没越过就在 `mouseup` 发一颗 `md-diagram-tap`（`bubbles`），由 widget 决定浮源码框。`mousemove` / `mouseup` 挂 `document`：只挂卡片会漏掉"拖出卡片之外松手"，图停在半路。
- 监听一律**捕获相**，且 `stopPropagation()` —— 这不是风格问题，见 B455-6。
- 卡片原来是 `overflow-x: auto`（图太宽就横滚）⇒ 改 `hidden`，平移缩放接管了这一格。

## B455-6 · markmap 让位 + 编辑入口重接线

脑图那颗 d3-zoom 在 mousedown 里 `stopImmediatePropagation()`（B454-2 的真凶），所以变换层必须**捕获相 + `stopPropagation()`**，它才收不到同一发；wheel 同理，否则一颗图自己缩两遍。判据在 `tests/preview-diagram-viewport.test.ts` 里自己造一颗掐冒泡的孩子。

编辑入口从"点图 = 冒泡档 mousedown"改成认 `md-diagram-tap`：拖过阈值不发包 ⇒ 不进编辑；纯点击发包 ⇒ 浮源码框，边改边重画（B454 那套）。

## 真机抓到的四条病灶（都先红后修；单测全绿着）

1. **右上角三颗键按不动**（`.tmp/b455-diagram-probe.py` 一轮 FAILS=6）。`DiagramWidget` 挂在 wrap 上的**兜底** mousedown 把"点在按键上"当成"点在图上"，直接 `preventDefault()` + 进编辑态。关键机制：**挂在祖先的捕获相比挂在后代的先跑** ⇒ widget（wrap）那条比变换层（card）那条先执行，放行清单必须列全两处。修法：`.md-diagram-canvas, .md-diagram-zoom` 一起放行（[src/preview/richWidgets.ts:308](../../../src/preview/richWidgets.ts#L308)）。jsdom 只挂一层，照不出来。
2. **WaveDrom 画成一排实心黑**（目视）。上一形是"给皮肤选择器加祖先前缀 `.md-diagram--wavedrom …`"：`<defs>` 里的**原件**在文档树里 ⇒ `getComputedStyle` 量着是对的，而真正画出来的是 **`<use>` 的克隆体**，它在那颗 use 自己的 shadow 树里，文档选择器跨不过边界 ⇒ 丢规则、`fill` 退回初始黑。jsdom 不做级联 ⇒ 单测完全照不出。修法见 B455-4。定案用的是真浏览器 A/B（现状 → 剥前缀 → `svg ` 前缀 → `.nope ` 对照），对照档必须变黑，否则整发求值没在量东西。
3. **波形信号名在暗档看不见**：皮肤给 lane 名那档 `.info{fill:#0041c4}` 特异度压过 `text{fill:var(--md-fg)}`。修法：树内补 `.info{fill:var(--md-accent)}`；`.warning/.error/.success` 是作者在 WaveJSON 里点名的状态色，留着不动。
4. **ECharts 标题在暗档几乎看不见**：根 `textStyle` 只管坐标轴/提示，**标题组件有自己的默认深灰**。修法：只给"对象形"的 `title` 补一颗 `textStyle.color = --md-fg`，作者写过的键逐颗让位（`title` 写成数组 = 多标题，整个不动，别把数组摊成对象）。

台子自己也红过两处（都是假红，记下来免得再踩）：判据把 `text` 按"自己带不带 class"分桶，漏了**从祖先 `<g class="info">` 继承**的那颗 ⇒ 正文色判据永远红；CM6 会把视口外的块 widget 卸掉，量之前必须先把那一格滚回视口（`focus()` 里先 `scrollTop=0` 再 `scroll_to`，因为 `scroll_to` 只会往下滚）。

## 要主动报出来的三条限制（不是偷偷 hack 掉的东西）

1. **光标停在图里时，滚轮归图不管翻页**（用户拍板"所有图表支持滚动缩放"的直接后果）。想改成"只有 Ctrl+滚轮才缩放"是一行的事，但那不等于"滚动缩放"。
2. **PlantUML 那张卡自带白底**，深色档下不会跟主题走（B452 选型后果：图是服务器画的）。
3. **编辑态实时重画会换掉整张卡片 ⇒ 缩放/平移状态回到 1:1**。重画走的是"新建一张卡"那条路，视图状态存在卡片上。判下来是"改源码就该看到新画的那张"，比"改完还保持你刚才放大到的位置"更符合直觉，所以没修；要反过来也做得到（把 view 提到 host 那一层）。
