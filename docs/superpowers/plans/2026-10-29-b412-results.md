用户口径（2026-10-29）：

> 是不是 inknote 里的名词，如果是则把这个前缀也去掉，这个预览模式就是 litepad 除源码模式外
> 唯一的预览/编辑模式」

拍板（三问三答）：

| 问题 | 选择 |
| --- | --- |
| 命名 | `preview` —— `src/preview/`、`preview.css`、`.md-preview-face*`、`previewFace` / `previewLock` / `togglePreviewEdit` |
| 改名方式 | 一次性脚本 + 全量门禁（tsc / vitest / cargo + diff 复核） |
| 20MB+ 大文件 | 新面全接（`huge` 档位闸整个删掉） |

`deco` **不是** InkNote 的名词（InkNote 源码 0 命中）—— 它是本仓库对 CM6 decorations 的缩写；
B397 起预览就活在装饰层上，前缀随旧臂一起删。

## 落成的模型

- 每格**一颗** `EditorView`；源码 / 预览 / 编辑三档是同一颗 view 的三种装束：
  `viewMode: "source" | "preview" | "edit"` + `previewCompartment`（`previewFace()` / `[]`）
  + `lock` Compartment（`previewLock()`）。
- 预览档 = **禁编辑的编辑档**（用户 2026-10-28 口径）：同一张装饰脸，差别只在
  `EditorState.readOnly` + `EditorView.editable(false)` + `tabindex=0`（能选字复制）+
  `transactionFilter`。
- 同步滚动只剩一层表面：`sideOfPanel()` 恒答 `"editor"`，`faceOf()` 只认 `EditorScrollAnchor(view)`。
- Markdown **哪一档**都装语言扩展：`perfProfileForDoc(cls, true).syntax === true`（含 huge）——
  没有解析器就没有装饰面，旧派生臂已删，不装等于预览只剩裸源码。

## 判据

- `tsc -b` 干净；vitest **118 文件 / 2046 例全绿**（`--no-file-parallelism`）；Rust **168 passed**。
- 真机台 `.tmp/b412-check.py`（debug exe + `LITEPAD_CONFIG_DIR` 隔离）**FAILS=0 / 28 PASS + 4 MEASURE**：
  - P1 配置里**没有** `deco_preview` 键 ⇒ 预览档照挂装饰面、只读锁在、派生面 0、标题装饰在、
    悬浮键可见、`contenteditable=false + tabindex=0`；
  - P2 配置里显式写 `"deco_preview": false` ⇒ **照挂**（旧开关已无任何闸门作用）；
  - P3 `Ctrl+E` 预览↔编辑：同面换锁、真输入进文档、`Ctrl+S` 落盘、再按回只读；
  - P4 `Ctrl+/` 源码档：装饰面摘掉、`mode-source`、正文裸 markdown，再按回预览；
  - P5 **21.4MB** md：装饰面照挂、标题装饰照画（7 条）、派生面 0。
- 截图：`.tmp/b352-check/b412-preview.png`（预览档）/ `b412-edit.png`（编辑档）。

## 已知边界

- 大文件解析从视口起步，跳到文末仍需从头铺语法树（large / huge 同一量级；VS Code 的大文件
  令牌化停止策略在本应用里会让预览名存实亡，故不采用）。
- `scripts/sync-scroll-probe.mjs` 的「编辑器 ↔ 派生预览」配对模型失去了被测面（开发者工具，
  不在门禁内），保留未改。
- `docs/superpowers/plans/` 下的历史计划/结果文档里的 `deco` 字样是当时的真名，不回改。
- 真机台坑：验收链里有个模块 import 时**无条件改写** `os.environ["LITEPAD_EXE"]` 指向
  `.tmp/b383-target` 的旧产物，第一版台子因此跑在 v0.24.58 上假 FAIL；`b412-check.py` 改为
  直接改模块的 `P.EXE`（`LITEPAD_B412_EXE`）。
