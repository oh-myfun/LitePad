## B408 · 多开应用实例

用户口径：「支持一下多开应用实例（让开发测试不影响已安装应用的正常使用）」。

### 落地

| 面 | 做法 |
| --- | --- |
| 单实例插件（`src-tauri/src/main.rs`） | 注册改成条件式：`multi_instance_allowed()` 为真那一路**不装** `tauri_plugin_single_instance`（两个进程各自开窗、各自转关联文件）；否则照旧装，回调抽成具名 `on_second_instance`（原闭包一行未改） |
| 判据（纯函数 `multi_instance_from`） | `dev_build` 默认多开；`LITEPAD_MULTI_INSTANCE=1/true` 强制多开；`LITEPAD_SINGLE_INSTANCE=1/true` 强制单实例；两个都设时 MULTI 赢；其它取值忽略 |
| 配置目录（`src-tauri/src/session/mod.rs`） | `LITEPAD_CONFIG_DIR` 仍最优先；否则 `%APPDATA%\LitePad`（发布）/ **`%APPDATA%\LitePad-dev`（debug 构建）**。纯函数 `pick_config_dir` 便于断言 |
| 门禁守卫（`tests/file-association.test.ts`） | B313 的三条源码形状守卫改钉新形状：回调函数体 + `builder.plugin(tauri_plugin_single_instance::init(on_second_instance))` 仍在「单实例那一路」 |

### 证据

- Rust：`cargo test --release` → **169 passed / 0 failed**（含 `multi_instance_from` 6 条：dev 默认多开、release 默认单实例、MULTI 强制、SINGLE 强制、MULTI 优先、取值忽略；`pick_config_dir` 3 条与 dev 叶目录 1 条）。
- 真机（`.tmp/b409-check.py` C 段，进程级，同一验收 exe）：
  - M-01 默认（不设环境变量）：第一发窗口起来（hwnd 21371372）；第二发 4 秒内自己退出（`b_alive=False`），第一发仍活 —— 单实例转发没坏；
  - M-02 `LITEPAD_MULTI_INSTANCE=1`：两发都活着（`{'a': True, 'b': True}`）—— 多开生效。
- 已知边界：`LitePad-dev` 叶目录只在 **debug 构建**生效；真机台用的是 release 验收 exe，这一格由 Rust 单测 `config_dir_dev_build_uses_separate_leaf` 钉住（真机只验了环境变量覆盖与单/多开行为）。

## B409 · 编辑模式三件

用户口径：「1、html块中的相对路径图片没有正常渲染（比如LitePad.md中的截图）；2、代码块的语言选择组件放在区块的左边，代码区块顶部空白空间太大。3、代码块语言选择下拉列表复用语言模式的图标，且完善支持的语言数量」。

### 1. HTML 块里的相对图片（`src/spike/deco/miscWidgets.ts`）

- `HtmlBlockWidget` 新增 `mdPath` 参数（`previewSets` 把 `assetBase` 的文档路径喂进来），`eq()` 认它 ⇒ 换文档时 DOM 不复用旧目录的图；
- `toDOM` / `updateDOM` / `onInput` 三条路都跑 `resolveHtmlImages()`：只对**相对路径**做 `resolveAssetPath` + `assetUrl`；
- ⚠️ 协议判据只放过 `https?` / `data` / `blob` / `asset` 与 `//`：`C:\shots\a.png` 也带冒号，一刀切会把 Windows 绝对路径跳过（单测有钉子）。

### 2. 语言选择左置 + 顶部收窄（`codeBlockWidget.ts` / `deco.css`）

- 工具行 `justify-content: flex-end → space-between`：语言选择在左、复制键在右（DOM 顺序不变，语言控制仍是第一颗）；
- 尺寸收紧：工具行 30→**24px**、语言按钮 26→**20px**、复制键 26→**20px**、代码区上内距 12→**6px**、行号栏上内距 12→**6px**、工具行左右内距 8→6px；
- 真机读数：工具行高 **24px**、盒顶到代码区 **25px**（旧口径 30 + 12 = 42）。

### 3. 下拉图标 + 语言表扩容（`src/shell/dropdown.ts` / `codeBlockWidget.ts` / `global.css`）

- `DropdownOption` 加 `icon`（HTML 片段）；选项行与触发器都按 `.dd-main`（图标 + 文字编组）渲染，触发器 `space-between` 不会把图标与文字拆到两头；
- 语言表从 24 项扩到 **55 项**（顺序对齐 `src/editor/language.ts` 注册表，只收 Shiki 认得的 id：`@shikijs/langs` 全集逐条试过；Octave / VBScript 没有对应语法不进表）；
- 图标走 `fileIconHtml()`（Seti），与状态栏语言模式、标签页同一个出口；
- 常见别名 `sh` / `bash` / `js` / `ts` / `py` / `yml` / `cpp`… 只在**显示与选中项**上归到规范条目，**不改写**围栏里原有的写法（用户没点过列表时回写继续用源码原词）。

## 已知边界

- 纯文本项在代码块下拉里叫「纯文本」（图标借 `Plain Text`）；语言模式浮层仍叫 `Plain Text` —— 两处是不同控件，没有并成一份表；
- 别名只做显示归一，选中后会写成规范 id（`sh` → `shellscript` 那次是用户主动选的，等于换档）；
- 页面缩放不是整数时，`getComputedStyle` 与 `getBoundingClientRect` 可能不同单位（B407 量到 1px→0.6667px）；台子按 header 自身的 rect/computed 比值归一后再判 CSS 口径；
- B408 的 `LitePad-dev` 叶目录未在真机验（验收 exe 是 release），见上。
