## B457-1 · 脚注 2：两条定义紧挨着，第二条被第一条整段吃掉

取证是「语法树 dump 而不是猜」：这一份与已修好的 B449 那份**只差一处** —— `[^1]: …` 的下一行就是
`[^bignote]: …`，中间没空行。CommonMark 的**惰性续行**于是把第二行并进第一条的段落，
`FootnoteDefinition` 一路长到 45-192（把第二条连同它的缩进正文整个吞了）⇒ 装饰层只折出**一张**卡片。

GFM 的口径是定义体只吃「缩进 ≥4」的行：顶格的 `[^x]:` 是新的一条，不是上一段的续行。
缺的是 `endLeaf` 那一发（与 lezer 自己给 Table 的那条同一形）：段落续行前先问一句「这一行是不是另一条定义」。

判据：[tests/preview-footnote-syntax.test.ts:446](../../../tests/preview-footnote-syntax.test.ts) —— 解析层两条各一个节点 + 装饰层两张卡各自带自己的正文。

## B457-2 · 五线谱不完整 + 「窗口缩放不自动刷新」：CM6 把 A 图种的 DOM 嫁接给了 B 图种

「缩放不重画」的真凶不在 ResizeObserver，在 CodeMirror 6 的块 widget 复用：
`findWidget` 第一趟**只比构造函数**，于是同一格里换了图种（`mermaid` ↔ `abc`）时那份 DOM 被原样端过来。
`attachWidthRefit(inner, kind, …)` 看到「已经挂过」就早退 ⇒ 那颗 observer 从来没为这一任住户挂上。

修法：`DiagramWidget.updateDOM` 里按「图种变了」拆掉旧挂载再重挂（[src/markdown/diagrams.ts](../../../src/markdown/diagrams.ts)）。
判据：`B457-2b · 不同图种不许共用同一份 DOM` + `B457-2 · 卡片宽度变了要按新宽度重画`（数动笔次数，不数像素）。

真机（`.tmp/b457-probe.py`，改窗口宽度而不是页面里 style 糊弄）：abc 随宽重画 1025 → 547 → 1025，ECharts 同跟。

## B457-4 · 深色档波形泛白：皮肤那八档是给白纸调的

`wavedrom/skins/default.js` 里 `.s7`–`.s14`（WaveJSON 的 `2`–`9`）写死近白粉彩
（`#fff` / `#fffb4` / `#ffe0b9` / `#b9e0ff` / `#ccfdfe` / `#cdfdc5` / `#f0c1fb` / `#f5c2c0`），
`.s5`=`gap` 是 `#fff`、`.s6`=`Pclk`/`Nclk` 是 `#000` ⇒ 落在 `#242526` 的卡片上就是「泛白 + 一道白痕 + 看不见时钟标记」。
逐颗是谁我用 `.tmp/b457-skin-walk.cjs` 走了一遍皮肤对象，不靠猜。

修法（[src/markdown/diagrams.ts](../../../src/markdown/diagrams.ts) 的 `wavedromInk()`）：暗档才覆盖，八档从**共用调色板**派生
（`accent/yellow/orange/blue/blue+green/green/purple/red` 各压向卡片底 `DATA_STATE_DARKEN = 0.45`），
`.s5` 跟卡片底、`.s6` 用 `var(--md-fg)`；**浅档一字不改**。覆盖那颗 `<style>` 挂在皮肤之后、选择器不带前缀
（`<use>` 克隆体跨不过祖先前缀，见 B455-7 那条 pitfall）。

判据：`B457-4 · 深色档的波形数据格不许泛白`（jsdom 里逐颗算亮度/彩度，并断言浅档十颗全为 `null`）。

真机（`.tmp/b457-8-check.py`，shadow root 里读**计算色**）：暗档 8/8 亮度 < 0.5、彩度 ≥ 28、彼此 ≥ 6 种不同色、
`gap = rgb(36,37,38) == --code-bg`、`s6 = rgb(187,190,191)`；浅档 8/8 逐字仍是皮肤原色。
目视结案：`.tmp/b352-check/b457-8-dark-wd.png` —— `head/body/tail` 三块是橄榄绿/橙/蓝，数据标签近白落得上去。

## B457-5 · 五线谱右缘被裁：B457-2 那笔账我只算了一半

abcjs 的 SVG 总宽 = `staffwidth + paddingleft + paddingright`，墨迹占 `[paddingleft, paddingleft + staffwidth]`。
B457-2 我把两颗 padding 归零 ⇒ `svg.width == 格宽`、墨迹右沿**正好顶在 SVG 自己的边界上** ——
而 SVG 根节点裁掉自己的溢出 ⇒ 右对齐的署名（`C: Paul Rosen`）尾字被切。

修法：`ABC_INK_MARGIN = 15`（abcjs 默认那一档），`staffwidth = 卡片内容宽 - 2×15`、
`paddingleft = paddingright = 15` —— 总宽仍等于格宽，墨迹左右各留一档白。

判据：`B457-5` 那条按**总宽**算账（`staffwidth + paddingleft + paddingright === 860`，重画那一发 `=== 660`）。
真机：`overAttr = -15`、`overAvail = -15`、`inkX = 15`（浅档暗档各一次）。

## B457-6 · 流程图排布：不是 11/12 的版本差，是布局器差

台子 `.tmp/b457-mermaid-cmp/index.html`（同一页并排跑多臂多图种，量 `getBoundingClientRect` 再按 SVG
屏幕/固有宽换算回用户单位；拐点 = 每根 path 采 48 点找 >20° 的转向）。样例文档那张 `graph TB` + one/two/three：

| 臂 | 区块排布 | 拐点 | 图幅 |
|---|---|---|---|
| 我们的配置（默认臂） | 并排 1 / 叠 1（`one@20,301` 在 `three` 下面） | 6 | 484×522 |
| `flowchart.layout:'layered'` | **并排 3 / 叠 0**（`one@740,16`） | **0** | 950×254 |
| Vditor（mermaid 11.15.0 原样配置） | 并排 3 | — | 638×262 |

⇒ 换布局器就够，**不降依赖**。三把候选键只有一把生效（其余是「配了但没生效」的哑配置）：

- `flowchart.defaultRenderer:'layered'` ⇒ 几何与不写**逐字节相同**；
- `flowchart.layout:'elk'` / `look:'elk'` ⇒ 同样不生效；
- `flowchart.layout:'layered'` ⇒ 生效。它走的是 mermaid 自带那颗 ELK 分片
  （`layout` 注册表里 `{name:'layered'}` 由 elk 那一支 map 出来），首次画流程图懒加载 `elk-*.js`（构建产物里本来就有，约 1.4 MB）。

**键位写在 `flowchart` 这一族，不写全局那颗 `layout`**：实测全局那颗除了流程图还会挪状态图（382→332）与
类图（286→296），而用户点名的只有流程图；时序图 / 甘特图 / 脑图 / journey / pie 两种写法下都逐字节不变。
`layered` 下能力面没缩水：边标签在、`classDef` 底色与 `linkStyle` 描边各 2 种、节点/边计数不变、嵌套子图仍包在里面。

顺带查出来的一件事：`curve` / `padding` / `nodeSpacing` / `rankSpacing` 这四颗在**旧的默认臂上是死的**
（42/48 改成 200/200，几何 484×522 一毫不变），换了 `layered` 才真吃（同改 → 1728×716）。
所以我们原本就在写的那几颗现在终于有意义，且 42/48 给的正是紧凑那一档。

判据：[tests/mermaid-theme.test.ts:155](../../../tests/mermaid-theme.test.ts) 两条 —— 一条钉 `flowchart.layout === 'layered'`，
一条钉**全局那颗必须没有**（谁以后写成全局就红）。
真机（同一张卡片在屏幕上的真实矩形，浅档暗档各一次）：`three@104,1284 228×285` 与 `one@864,1284 214×285`
垂直重叠 285px（= 矮块整高）⇒ 左右并排，节点 6 颗一个没少。目视：`.tmp/b352-check/b457-8-dark-mmd.png`。

## 台子自己踩的坑（两条，都写进判据注释了）

1. `b451` 那颗 `scroll_to` 把 `.cm-line` 与各种 widget 混在同一张节点表里找文本，命中的那一条属于**另一张脸**
   （预览档里源码那张脸也挂在同一个 `.panel-host` 下，只是不可见）⇒ `scrollIntoView` 滚的是那张脸的
   `.cm-scroller`，而我读的是 `querySelector` 捞到的第一颗 —— 滚对了元素、读错了元素，于是「卡片找不到」被记成了产品的病。
2. `scrollHeight` 会**边扫边长**（后面的图卡建出来文档就变长：同一篇实测 3707 → 8457）⇒ 开局缓存一次 `max`
   的那版在 3707 就收摊，WaveDrom 那一格根本没进过视口。现在每一发都重读 `max`。
