主路径（J1–J4）本来就通 ⇒ 用户撞的是 K1 / K3 这两支「点下去什么都没发生」。

## 根因（`src/search/panel.ts` 的 `jumpToLine`）

1. **信任结果里的 `docId` 快照**。`FileGroup.docId` 是**搜索那一刻**记下的；搜完之后用户
   可能把标签关了（`docs` 里那条还在、`tabs` 里没实例）、也可能把标签拖去了别的窗口
   （本地只剩 `panelId < 0` 的隐藏实例）。照单全收的话 `instancesOfDoc(docId)` 要么空、
   要么拿到看不见的那份 ⇒ 直接 `return`，**不重开、不报错、没有任何反馈**。
2. **不激活目标面板**。只 `switchTab(inst.panelId, …)` 不把那格设为活动，用户在**眼前那一格**
   里等跳转——活动格没变，看上去就是「点了没反应」。

## 修法

```ts
let docId = openDocIdFor(path);                       // 现场问一遍标签表（B419 就有的出口）
if (docId !== null && visibleInstancesOfDoc(docId).length === 0) docId = null;
if (docId === null) docId = (await doOpen(path)) ?? null;  // 复用 / 取回远程那份 / 新开，它都管
const inst = visibleInstancesOfDoc(docId)[0];
if (inst.panelId !== activePanelId) markActivePanel(inst.panelId);
switchTab(inst.panelId, inst.tabId);
reveal(inst, line, column, length);
```

- `visibleInstancesOfDoc` 而不是 `instancesOfDoc`：隐藏实例（`panelId < 0`）跳了也看不见。
- `markActivePanel`（`src/ui.ts`）就地同步 `.layout-panel-active`，**不重建标签条** —— 复用
  「点面板切活动格」那一套，不新造第二种画法。
- 多面板/多窗口的打开语义全交给 `doOpen`：它自己会记「最近打开」、取回远程标签、按落点面板新开。

## 判据

`tests/search-panel.test.ts` 新增 `B420 · 点结果行要跳到位` 三条：

1. 开着的文档：选中命中本身（`sliceDoc === "aa"`）+ `switchTab` 发到该格 + **不发** `doOpen`；
2. 标签关了：`h.opened` 收到路径（旧快照不许当「它还开着」用），重开后选区落在命中；
3. 文档在另一格：`activePanelId` 跟到那一格、`switchTab(1, …)`。

## 台子坑（这轮自己踩的）

- **`bc.write_config` 的 `sidebar_off` 只在 `launch()` 里设 `BENCH_SIDEBAR` 才为假**：K1–K3
  直接调 `bc.write_config` + `P.launch()`，侧栏整块 `display:none`，结果行 `rect` 恒 0 ⇒
  点到 (0,0) 上，第一轮 7 条 FAIL 全是假的。探针里显式写 `settings.json.sidebar_off = false`。
- **活动面板的 `data-panel-id` 从 1 起**（会话里写 0/1 会映射成 1/2）；认「哪一格」按
  `.layout-panel-active` 的 `data-panel-id` 读，别按 0 起猜。
- **`#sb-pos` 报的是选区 `head`**（选区末），点命中后列号 = 命中首列 + 命中长度，
  判据写「行号前缀 + 选中文本」两项，别写「列 1」。
