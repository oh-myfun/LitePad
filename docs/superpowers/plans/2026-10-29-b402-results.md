## ① 多行任务项：勾选框贴首行

- 病根：`.cm-line` 折行后**仍是一个元素**（高 = N 行），方框用的是 `top: 50%` +
  `translateY(-50%)` ⇒ 居中在整块上。真机基线：任务行 42px（两行），方框中心 600、
  首行文字中心 582 —— 差 18px。
- 修法：方框纵向锚点改成「首行中线」，行距取用户的 `--editor-line-height`（无单位）：

  ```css
  .md-deco .cm-line.md-task-item {
    --md-task-box-top: calc(var(--editor-line-height, 1.5) * 0.5em - 0.5em);
  }
  .md-deco .cm-line.md-task-item::before { top: var(--md-task-box-top); }
  .md-deco .cm-line.md-task-done::after { top: calc(var(--md-task-box-top) + 0.17em); }
  ```

  勾（`::after`）与方框共用**同一个变量**，折行时一起留在首行。
- 真机：方框中心 **519 = 首行中心 519**（修前差 18）。派生预览的 `input.md-task` 本来
  就是行内元素，量到 394 = 394，不动。

## ② 标题字号：先修连乘，再谈档位

- 病根不是「档位选大了」，而是**同一档写了两次**：字阶类挂在 mark 上，`*` 后代规则又写了
  一遍 `font-size: 1.92em` —— 语法高亮那层 span 相对父级 mark 再乘一次。
  真机基线：h1 的 mark 26.88，但**内层 span 51.61px**（1.92² × 14）；h2 32.35、h3 22.58。
- 修法：**字阶只在 mark 上写一次，后代一律 `inherit`**（字号/字重/字距三样）；
  `#` 的每级规则同样拆成 mark 本体 + `*` inherit。h6 的 `*` 另补 `color: var(--md-muted)`
  （原来颜色写在合并块里，拆开后内层会掉回正文色）。
- 真机：h1 26.88 = 内层 26.88、h2 21.28、h3 17.78、h4 15.68、h5 14.28、h6 13.3；
  h1 行盒 92.8 → **55.7px**。基准对齐：InkNote 编辑面 1.92/1.52/1.27（15px 正文）、
  VS Code 预览 2/1.5/1.25（14px 正文）；本仓正文 14px ⇒ 26.88/21.28/17.78 与两边同档。
- 派生预览补 h5/h6 显式档位（`--md-h5-scale: 0.875` / `--md-h6-scale: 0.85`，VS Code 同值）：
  此前没写，落到浏览器默认的 0.83/0.67，h6 只有 10.05px。现在真机 **13.13 / 12.75**。

## ③ HTML 渲染照 VS Code 预览

三件事，缺一件都会「看着不像」：

1. **不再套卡片**：`.md-html-preview` 撤掉 InkNote 的虚线框 + 底色 + 内边距（VS Code 的
   预览里原始 HTML 就是文档正文的一部分）。
2. **排版同源**：`HtmlBlockWidget` 给容器多挂一个 `.md-rendered`，表格线、段落间距、
   标题下边框、链接色、代码 chip 与派生预览**同一份规则**（不另抄一套）；deco.css 里只把
   字号/行距/颜色压回继承（预览根会 +1px、行距 1.7）。首末子元素贴边规则写在 preview.css
   （deco.css 禁纵向 margin）。
   真机：块内 h2 = 19.6（1.4 × 14）且有 0.67px 下边框、th 有底色、标题↔段落间距
   **12px（与派生预览同值）**。⚠️ CM6 的 `.cm-content` 是 `white-space: pre-wrap`，会一路
   继承进 widget —— HTML 源码里标签之间的换行曾变成 21px 的**可见空行**（间距量到 43px），
   容器必须压回 `white-space: normal`。
3. **内联 HTML 也渲染**（此前整段是源码）：`previewSets` 新增 `HTMLTag` 分支，白名单
   `kbd / mark / u / sub / sup / b / strong / i / em / s / del / span` 成对藏掉标签、
   中间文字挂样式；`<span style="color:…">` 只认 `color` / `background-color`（值只放
   hex 或颜色关键字）。光标压进元素时两个标签一起显形（与 `**` 同一套露出口径）；
   表格 / 围栏 / 行内代码里的标签不碰（已被整段接管）；**未知标签与没闭合的标签保持源码**。
   真机：`kbd` 12.6px 等宽、`mark` 有底色、`u` 下划线、`sub/sup` 分别 vertical-align
   sub/super，正文里 `<kbd>` 这类字符不显形。
4. **消毒放宽**（sanitize.ts）：VS Code 的预览不剥 `style`（CSP 只挡脚本），我们原来只给
   `<span>` 留三条。现在按**展示类属性白名单**（颜色/边框/内外边距/字号字重/对齐/宽高/
   行高/vertical-align/table 属性…）对**所有元素**放行；`position / display / z-index /
   transform / inset / overflow / float / behavior` 与 `url()` 一律不放。

## 踩到的坑

- **em 连乘**：同一个档位写在「元素 + 后代」两条规则里，后代那条相对父级再乘一次。
  凡是 em 字阶，后代只能 `inherit`。
- **`ruleBlock` 的 member 回退**：把一条列表规则拆成两条后，`ruleBlock(css, ".md-deco .md-sub")`
  会命中「列表成员」那条（`.md-sub, .md-sup`），拿到别人的块体 ⇒ 要用 filter 词（如
  `"vertical-align"`）钉住本体。
- **台子的选择器口径**：`document.querySelector('.cm-content, .md-rendered')` 取的是**文档序
  第一个**匹配 —— 派生臂里还有隐藏的 `.cm-content`（源码原文），会把源码里的 `<kbd>` 算成
  「标签没渲染」（假红）。文本只取被测元素 `closest()` 到的那一层容器。
- **Mark / MarkText 系统色**：`<mark>` 的浏览器默认底色用 CSS 系统色复刻（deco.css 禁十六进制）。

## 边界（本轮不做）

- 内联 `<img>` / `<video>` / `<br>` 仍按源码显示（块级图片走 markdown 图片 widget 那一套）。
- `<style>` 块照旧剥掉（允许它等于把整个应用的样式交给文档）。
- 行内 HTML 的白名单外的标签（自定义组件、`<font>`）保持源码显形。
