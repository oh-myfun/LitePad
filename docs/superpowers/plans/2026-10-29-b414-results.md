# B414 结果 · 标题留白「上 0 / 下递减」+ 文首文末贴边（含紧贴前文的 24px）

用户口径（2026-10-29）：

> 标题统一改成顶部 padding 归零，底部递减是否可行？
> 可以，并补第一条边界。

参照：本地 VS Code 1.143 的 `extensions/markdown-language-features/media/markdown.css`
（`html,body { padding: 0 26px }` + `body { padding-top: 1em }`；`h1..h6 { margin-top: 24px;
margin-bottom: 16px }`，其中 `h1 { margin-top: 0 }`）。

## 最终口径

| 位置 | 值 |
| --- | --- |
| 文件上沿 | `.cm-content { padding: 1em 0 0 }`（真机 14px） |
| 文件下沿 | 0 |
| 标题上留白 | **0**（所有级别） |
| 标题下留白（叠在源码空行 ≈21px 之上） | h1 12 / h2 9 / h3 6 / h4 3 / h5-h6 0 |
| 紧贴前文的标题（前一行非空） | **0**（用户后续口径：「去掉 md-heading-after-text」） |
| 紧跟分割线的标题 | 0（线条自身有 8px 下留白，避免线上下不对称） |
| 文首/文末的块级 widget | `.cm-content > .md-block:first-child { padding-top: 0 }`、`.cm-content > :last-child { padding-bottom: 0 }` |

为什么下留白是「额外量」而不是绝对值：空行不折叠是 B300 的硬约束（折叠会改行盒高度，
同步滚动逐行对齐必差）。真机空行 = 21px，所以标题后的最小间距就是 21px，
VS Code 的 16px 下外边距在这套模型里做不到，也不需要。
