## B428-1 · 一颗键管两层

**病灶**：B427 的过滤框里并排放着两颗键 —— 「使用排除设置与忽略文件」与「跟随
.gitignore / .ignore」。前者的文案已经把后者包含进去了：Rust `NameWalk` 里那层忽略清单
的有效判据本来就是 `use_excludes && use_ignores`，把总闸关掉时 `use_ignores` 写什么都
不生效。两颗键并排摆，用户读到的却是「两个独立开关」。

**修法**：删掉第二颗（HTML / `ui.ts` 的 ref 与导出 / panel 的取节点、接线、亮灭同步 /
`FilterOpts.ignores` 与 `DEFAULT_FILTER`），`useIgnoreFiles` 直接跟随 `filter.excludes`：

```ts
exclude: filter.excludes ? (settings?.search_exclude ?? "") : "",
useExcludes: filter.excludes,
// B428（用户点名）：那颗键的文案本来就是「使用排除设置**与忽略文件**」——
// 忽略文件跟随同一颗总闸，不再有旁边那颗独立的「跟随 .gitignore / .ignore」。
useIgnoreFiles: filter.excludes,
```

**判据**：

- `tests/explorer-filter.test.ts`：`DEFAULT_FILTER` 不许再留 `ignores` 这一格；
- `tests/explorer-panel.test.ts`：`#explorer-filter-ignores` 不存在；关掉这一颗 ⇒ 交给
  Rust 的两格一起变 false（`useExcludes:false, useIgnoreFiles:false`）；再点开又都 true；
- `tests/explorer-contract.test.ts`：HTML / ui / panel 三处 `explorerFilterIgnores` 一起消失，
  剩下那颗的 `data-tip` 与 `aria-label` 都是「使用排除设置与忽略文件」。

## B428-2 · 过滤框的边框

**病灶**：`.explorer-filter-field` 只写了 `flex: 1 1 auto`，而全局 `.find-field` 是
`border: none`（悬浮查找条与侧栏搜索共用的底样式）。侧栏搜索那边有一条自己的
`.search-field { border: 1px solid var(--border) }` 把它补回来，过滤框没有 ⇒ 与面板同底色，
看不出哪一截能打字。

**修法**（口径逐字照侧栏搜索）：

```css
.explorer-filter-field {
  flex: 1 1 auto;
  min-height: 26px;
  border: 1px solid var(--border, #d0d7de);
}
.explorer-filter .find-field:focus-within {
  outline: none;
  border-color: var(--accent, #06c);
}
```

焦点那条多一层 `.explorer-filter` 是为了压过 `global.css` 里悬浮条共用的
`.find-field:focus-within { outline: 1px solid … }`：只换这根线，不描内外两道环。

**真机**：`.explorer-filter-field` 计算值 `border-top: 0.666667px solid rgb(57,148,188)`，
`min-height: 26px`，焦点时 `outline-style: none`、边框色 = `--accent`；**失焦后边框色
= `--border`（`rgb(42,43,44)`）**——线在，只是不扮焦点色。⚠️ 0.666667px 不是缺陷：
DPR 1.5 下 Chromium 把 1 CSS px 的边框按设备像素取整，判据必须换算（`bw × dpr = 1`），
写死 `== "1px"` 会把正常机器判成 FAIL（首跑就撞了这一下）。

## B428-3 · 过滤态的「全部折叠/展开」

**病灶**：头那颗键走 `collapseAllHere()`，它只动 store 的 `collapseAll()` 与
`rootsCollapsed` —— 过滤态的画法读的是另一册 `filterCollapsed`，两边不相干 ⇒ 过滤时点它
等于什么都没发生（键看着活着）。

**修法**：

- `filterDirPaths()`：命中树里**带子项**的目录（DFS 树序 ⇒ 下一行更深即代表有子项）；
  各根的根行不在内（全折不碰根行，与常规树口径一致）。
- `foldState()`：`{ dirs, folded }`，头部键与右键菜单那一项共用。
- `syncCollapseButton()`：图标 / `aria-label` / `data-tip` / `aria-pressed` 跟着
  「全折 / 未全折」翻；**过滤态且命中里一个可折目录都没有 ⇒ `disabled`**，不做按下去
  没反应的死键。`renderTree()` 现在是「`paintTree()` + 这一发」的包装器，三十来处调用点
  谁都不必记得补第二发。
- `collapseAllHere()`：过滤态里全收着 ⇒ `filterCollapsed.clear()`（连手动收起的根行一起
  放开），否则把 `filterDirPaths()` 全部收起来；只动 `filterCollapsed`，store 的展开缓存
  一个不碰。

**判据**（单测，全部经真实事件）：

- 过滤命中 `notes/deeper.md` ⇒ 点「全部折叠」只剩根行 + `notes`；图标 `expand-all`、
  文案「全部展开」、`aria-pressed=true`；再点一下命中行全回来、三处一起复位；
- 命中只有根级文件（`only.md`）⇒ 键 `disabled`，文案不乱改；Esc 回常规树 ⇒ 键活过来、
  文案回「全部折叠」；
- 契约：`collapseAllHere` 的函数体必须出现 `filterOn()` 与 `filterCollapsed`；
  CSS 里那两截（`border: 1px solid var(--border…)`、焦点只改 `border-color`）逐条钉住。

**真机**（S3）：过滤「针」⇒ 全折后行集 = `["copy-针.md", "deep", "inbox", "notes"]`
（`deep/deeper/深处针.md`、`notes/plan-针.md`、`inbox/moved-针.md` 都藏了；根级命中
`copy-针.md` 不归任何目录管 ⇒ 留着，这是对的），`aria-label`/图标/`aria-pressed` 三者
同步翻；展开复原；「ping」只有根级命中 ⇒ 键 `disabled=true`；回到「针」⇒ 又活。
另验：关掉「排除」⇒ `.gitignore` / 设置页排除 / 噪声目录三层一起放开，点回来又全挡
（一颗键管两层）；`#explorer-filter-ignores` 在真机 DOM 里不存在。
