# B407 · 编辑模式：YAML Front Matter 块 + 对照 InkNote 的块级审计

用户（2026-10-29）：

> 编辑模式：YAML块（智能体技能等）支持下，另外对照inknote检查下还有没有遗漏的未支持的块。

## 一、YAML front matter 折成可编辑块

以前这一段在装饰面里是「整段跳过、原样显示」：lezer 会把 `title: x` + `---` 判成
SetextHeading2，只能不加装饰。智能体技能（`SKILL.md`）的 name / description 就这么裸着。

现在照 InkNote 的 `FrontMatterWidget` 补一块：

- `frontmatterWidget.ts`：标签（固定 "YAML Front Matter"）+ **常显**的 YAML 文本区；
  `toMarkdown` 按 `---\n…\n---` 回写；点盒子留白进入编辑、点文字直接改；
- `codeFence.ts#frontMatterBody`：取首尾围栏之间的正文（去掉闭合行后的那个换行）；
- `previewSets`：整段变成一块原子块 + 一颗块替换 widget（`blockReveal`，不跟光标显形）；
  两条 `---` 之间没有任何 `key:` 的（文档开头的分割线）不折 —— 照 InkNote 的防吞判据；
  数学扫描补 `m.from < fmEnd` 一道闸（front matter 里的 `$` 不许再塞行内公式，否则与块替换交叠）；
- `deco.css`：标签 11px `--md-faint`，盒子描边/底色取 `--md-panel-border` / `--md-panel-bg`；
  `.md-frontmatter-source` 把 `.md-block-source` 的 `display:none`、边框、底色压回去（常显）。

**真机抓到的通病**：只读档里 IME 组合与程序化 `insertText` 不走 keydown，会先改 widget 的
DOM —— 文档没变、画面上却凭空多字。`attachSourceEditing` 补一道 `beforeinput` 闸
（`readOnly` 时 `preventDefault`），所有块组件一起受益。

## 二、对照 InkNote 的块级覆盖审计

InkNote 的装饰面节点表（`src/editor.ts`）+ widget 清单逐条对过：

| InkNote 能力 | LitePad 装饰面 | 备注 |
| --- | --- | --- |
| YAML front matter | ✅ 本轮补齐 | 可编辑块 |
| 围栏代码 / 缩进代码 | ✅ | 语言下拉、复制、行号俱在 |
| 表格（对齐 / 增删行列） | ✅ | 工具栏比 InkNote 还全 |
| 图片（块 / 行内） | ✅ | 块图点开改源码 + 悬浮键弹窗（B406） |
| HTML 块 | ✅ | 多一套消毒 + VS Code 口径（B401） |
| 公式 / mermaid | ⚠️ 能画不能就地改 | InkNote 有源码区就地编辑 + 放大/复制工具栏 |
| 链接定义 / 脚注定义与引用 | ✅ | |
| 行内 HTML（u/mark/b/i/kbd/s/sup/sub/span） | ✅ | 白名单 + `span` 的 color/background-color |
| 任务 / 引用 / 列表 / 标题 / 分割线 / 实体 / 硬换行 / 转义 / 自动链接 | ✅ | |
| `==高亮==` | ❌ | lezer 不认；InkNote 走全文正则 |
| `<br>` | ❌ | 当前按源码显示；InkNote 直接藏掉 |
| 图片粘贴管线（pendingImageUrl） | ❌ | InkNote 粘贴即插图；LitePad 无此管线 |

结论：**块级只缺 YAML front matter**，本轮已补；余下三处是行内/工具栏/管线差异，不涉及新块。

## 已知边界

- 闭合行写成 `...` 的 front matter 回写时会统一成 `---`（与 InkNote 同口径）；
- 分隔线与 frontmatter 同形（两条 `---` 夹段落）但没有任何 `key:` 时按普通正文显示（不折盒）；
- deco 关闭时的派生预览仍走 markdown-it：front matter 仍会被画成「分割线 + 大标题」（B394-6，
  另一条渲染臂，不在本批范围）；
- 公式 / mermaid 的就地编辑、`==高亮==`、`<br>` 隐藏、图片粘贴管线未做（见审计表）。
