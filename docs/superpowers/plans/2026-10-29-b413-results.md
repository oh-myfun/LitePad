# B413 结果 · 预览/编辑面收窄上下留白 + 删掉「预览行距」设置

用户口径（2026-10-29）：

> 预览/编辑模式中文件顶部和底部存在额外的大块空白高度，设置中的预览行距好像多余了。

## ① 上下大留白的根因

装饰面 `.cm-content` 的上下内距是 B397-2 从 InkNote 照抄的
`padding: clamp(32px, 6vh, 64px) 0 48px`。在 760px 高的窗口里它量出来是
**上 45.6px / 下 48px**（`.tmp/b413-measure.py` 基线），比正文本身的字号大一圈。

改成 `padding: 16px 0`（贴近 VS Code 预览：`body { padding-top: 1em }`、无底部留白）。
左右留白本来就不在这条上（画在 `.cm-line` 的 `--editor-padding-x`），不受影响。

⚠️ 本条的判据只钉 `.cm-content` 这一段；`.md-preview-face .cm-line` 的 `padding` 简写
规则特异度必须停在 (0,2,0)，别顺手给它补祖先链（B397-2 的教训）。

## ② 「预览行距」为什么多余

- 装饰面（预览 / 编辑两档）的行距走 `--editor-line-height`（「编辑器行距」那条设置），
  `--md-line-height` 从来只喂 `.md-rendered`。
- `.md-rendered` 现在只有两个消费者：导出 HTML 的文章体、预览面里的 HTML 块 widget
  （后者在 `preview.css` 里显式 `line-height: inherit`）。
- 也就是说这一项**只管导出件**，名字却叫「预览行距」——名不副实，删。

删除面（一处不剩，git grep 为空）：

| 层 | 删了什么 |
| --- | --- |
| Rust `Settings` | `preview_line_height: f64` 字段 + `Default` 里的 1.7 |
| `src/ipc/api.ts` | `preview_line_height: number` |
| `src/appearance.ts` | `applyPreviewLineHeight()` |
| `src/main.ts` | 启动时的 `applyPreviewLineHeight(...)` 调用与 import |
| `src/prefs.ts` | `setPreviewLineHeight()`、设置页 opts 里的 `previewLineHeight` / `onPreviewLineHeight` |
| `src/shell/settingsdialog.ts` | 接口字段、`PREVIEW_LINE_HEIGHT_OPTIONS`、那一行 numberSelectRow、搜索关键词 |
| `src/styles/preview.css` | `line-height: var(--md-line-height, 1.7)` → 常数 `1.7`（该变量已无人声明） |
| 测试 | 8 份 Settings 夹具的 `preview_line_height: 1.7`、settingsdialog 的初值/回调/关键词/6 项顺序、menubar 的函数名与设置项清单、`preview-face-style` 的 padding 断言 |
| 文档 | README 的「预览行距」、`test-data/预览排版样例.md` 那句注释 |

旧 `settings.json` 里残留的 `preview_line_height` 键由 serde 的默认行为忽略
（`Settings` 没有 `deny_unknown_fields`），下次写盘即消失，不需要迁移代码。

## 已知限制

- 底部仍会看到大片空白——那是短文档没占满视口，不是 padding；`scrollHeight == clientHeight`
  时本来就没有可滚动余量。
- 「预览布局宽度」仍单独成组（「预览」小分组只剩它一项）。分组标题留着是为了将来
  加预览侧设置时有落点，不是为了好看。
