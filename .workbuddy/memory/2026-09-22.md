## 沙箱新坑：`bash` / `npm` 会撞 wsl 黑名单（记进 `ref/session-env.md` §11）

- 症状：`bash -c 'echo hi'` 返回乱码 + exit 1，报 `PROGRAM BLOCKED … wsl.exe`；
  `npm run <script>` 秒级失败，日志只有 UTF-16 的「拒绝访问。」（Read/Grep 都识别成二进制）。
- 根因：PATH 里 `/c/Windows/system32` 排在 Git 之前，而 Windows 自带
  `C:\Windows\System32\bash.exe` **就是 WSL 启动器**；`npm` 在 Git Bash 下是 bash 脚本，
  shebang `#!/usr/bin/env bash` → 跟着走 wsl。安全策略不可绕过。
- 处置：跑脚本用 Git bash 绝对路径 `"/d/Program Files/Git/bin/bash.exe"`；node 工具全部
  **直调 node_modules 入口**（tsc / vite / eslint / prettier / @tauri-apps/cli），cargo 用
  `/c/Users/maoyu/.cargo/bin/cargo.exe`。完整配方见 `ref/session-env.md` §11。
- 附带：Bash 工具的 PATH 只含 Git 的 `cmd/` 不含 `usr/bin`，故 `ls`/`grep`/`cp`/`tail` 全缺失 ——
  文件操作改 PowerShell（`Copy-Item`），看日志用 Grep/Read，别 `| tail`（会截断，见 `pitfalls/0095`）。
- 打包脚本当时落在 `.tmp/build-local.sh`（`.tmp/` 已 gitignore，不入库）；配方已入库到
  `ref/session-env.md`，下次照方重建即可，不要去改 `scripts/build-all.sh`（它用 npm，对用户是对的）。
