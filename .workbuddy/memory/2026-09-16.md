### ③④ 滚动条：2px + 无两端箭头（踩了个 Chromium 的坑）

**症状**：`::-webkit-scrollbar` 写了 `height: 2px`，实际出来的是**系统滚动条**——
两端带箭头、也压不细。

**根因**：全局 `*` 规则上写了 `scrollbar-width: thin; scrollbar-color: ...`
（B52 之前统一滚动条时加的）。**元素上只要指定了这两个标准属性，Chromium 就会忽略
`::-webkit-scrollbar`** —— 两条路只走一条。B53 在 `.panel-tabstrip` 上也写了
`scrollbar-width: thin`，所以 B53 交付时标签栏其实**也是系统滚动条**，只是没人细看。

**修**：在 `.panel-tabstrip` 上**复位** `scrollbar-width: auto; scrollbar-color: auto`，
让 webkit 自绘规则接管；然后 `::-webkit-scrollbar { height: 2px }` +
`::-webkit-scrollbar-button { display: none; width: 0; height: 0 }`（去箭头）。

> 通用教训：**「全局统一滚动条」和「某区域自绘滚动条」不能靠同一套属性叠加**，
> 后者必须先把标准属性显式复位。回归测试直接断言这两行 `auto` 的存在。

## 调研：VS Code 最新版标签样式 → 优化方案

用户要求「获取 vscode 最新版的 tab 标签样式，然后给出优化方案」→ 产出 **`docs/tab-style-plan.md`**（先只做方案，未动代码；方案 **B** 随后实施为 B55，见文末）。

### 关键研究结论（读的是 microsoft/vscode 源码，不是二手文章）

- 当前稳定版 **1.137.0**（2026-09-09）。"最新版标签"实际有**两种形态**，别混：
  - **经典**（stable 默认）：标签高 **35px**（compact 22px），源码常量在
    `editorTabsControl.ts` 的 `EDITOR_TAB_HEIGHT`；活动态靠底色 + 可选 `tab.activeBorderTop`；
    **标签栏原生滚动条被完全隐藏**，改 overlay 浮层。
  - **Modern UI**（1.129 起实验性 `workbench.experimental.modernUI`，**只有 Insiders 默认开**）：
    `contrib/modernUI/browser/media/tabs.css`，文件头自称 *"transparent, rounded, borderless pills"*。
    药丸高 **24px**（compact **20px**）；标签盒子 `border-block: 4px solid transparent` →
    **24px 药丸 + 上下 4px = 32px 命中区**（compact 档正好 **28px**）；药丸 `inset: 0 2px` 做横向间距；
    去掉描边；非活动文字降到 `color-mix(fg 50%)`；操作列做成 24px 绝对定位覆盖层 + 渐变淡入。
  - **Connected**（`connectedEditorTabs.css`，同门最新表达）：活动标签填充向下溢出标签行、
    顶/左/右 1px 描边底边透明，左右两个 `::before/::after` **凹圆角（shoulder）**把标签与编辑区
    缝成一条连续轮廓；编辑区外框 `::after` 画描边且 `border-top: 0`。

💡 **最有价值的发现**：Modern UI 的 **compact 档 = 20px 药丸 + 8px = 28px**，
与本项目 B54 的标签栏 **28px 完全同高** → 换成药丸可以做到**零高度变化**（不动 `.panel-tabstrip`
高度、不动滚动条余量、不引出「溢出↔不溢出」抖动）。因此方案推荐走 compact 档。

### 方案要点（详见 docs/tab-style-plan.md）

- **A 保守打磨**：只做 4 件低风险事（活动标签 `margin-bottom:-1px` 打断底边线"接通"、
  悬停加 1px 下描边、× 常显、间距 2→4px），约 20 行 CSS。
- **B Modern UI 药丸（推荐）**：20px 药丸 + 4px 间距，圆角 4px 无描边，2px 自绘滚动条塞进下面那 4px 里
  （从而**去掉"2px 恒定预留"**这个 B53 遗留的复杂度）。
- **C Connected**：在 B 上加 cap + 凹圆角 + 编辑区轮廓；风险最高（要动分屏下每块面板的轮廓，
  凹圆角在 WebView2 需实测），且 LitePad 是文档编辑器不是 IDE 外壳，编辑区轮廓会挤压紧凑布局。

### 预演的雷点（动手时必须一起改，否则出 bug）

1. **`.tab-insert` 的 `top/bottom` 跟标签高度绑死**，且现有回归用例只守护了 `scrollLeft` 那半，**高度那半没守护**。
2. **`.tab-flash` 关键帧写死结束态 `background: var(--bg)`** → 药丸化后不改就会闪完回旧配色（脚本测不出）。
3. **`.tab-action` 16px 槽位与 `padding-right`/`min-width` 耦合**，改 padding 要复核 3 汉字文件名不被 × 挤掉。
4. **非活动面板降亮度**规则要同步改（否则分屏时活动标签药丸仍在发亮，焦点判断反而更差）。
5. 新增主题变量必须**浅色/深色两套齐补**。

⚠️ 视觉确认与截图**必须在桌面环境**做（沙箱内 WebView2 起不来）。

## B55 标签改 VS Code Modern UI 药丸 + 滚动条 4px 塞进下间隙

提交 `c52e257`。用户指令：「执行方案 B，滚动条改成 4px 正好塞进下面的空隙里」。

### 改了什么（`src/styles/global.css`）

- `.tab`：`height: 24px → 20px`（compact 档）；`border: 1px solid transparent` → **`border: none`**；
  `border-radius: 6px 6px 0 0` → **`border-radius: 4px`**（药丸）；
  `padding: 0 6px 0 10px` → `0 8px 0 6px`；`color: var(--fg-muted)` →
  **`color-mix(in srgb, var(--fg) 50%, transparent)`**（照抄 VS Code 非活动标签的降透明度写法）。
- `.panel-tabstrip`：`gap: 2px → 4px`、`padding: 2px 4px 0 → 4px 4px 0`，**高度仍 28px**。
- 滚动条 `::-webkit-scrollbar { height: 2px → 4px }`、thumb `border-radius: 1px → 2px`；
  `::-webkit-scrollbar-button { display: none }` 保留。
- `.tab-insert` 的 `top/bottom: 2px → 4px`（跟着标签高度走）。
- 新增三档底色变量（**浅深两套主题齐补**）：
  深色 `--tab-bg-hover: rgba(255,255,255,.05)` / `--tab-bg-active: #2b2f34` / `--tab-bg-active-hover: #343940`；
  浅色 `--tab-bg-hover: rgba(0,0,0,.05)` / `--tab-bg-active: #fff` / `--tab-bg-active-hover: #e6e8eb`。
- `.tab:hover` → **`.tab:hover:not(.tab-active)`**；`.tab-active` 去掉 `border-color`，改 `background: var(--tab-bg-active)`；
  新增 `.tab-active:hover { background: var(--tab-bg-active-hover) }`。
- **非活动面板降亮度规则连 `:hover` 一起覆盖**（否则鼠标划过非焦点面板药丸「亮回来」，比不降级更迷惑焦点）。
- **`@keyframes tab-flash` 结束态 `background: var(--bg)` → `var(--tab-bg-active)`**（0%/70% 的 color-mix 同理）——
  不改就会「闪完回到旧配色」，一帧的 bug，断言才测得到。
- 顺手删死代码 `.tab-dragging` / `.tab-drag-over`。

💡 **几何不变量（改标签栏前必读）**：28px 标签栏 = **4(上间距) + 20(药丸) + 4(下间隙)**；
**那 4px 滚动条正好吃掉下间隙**，所以滚动条出现/消失都不改变栏高（这才是「塞进下面的空隙」的真正含义）。
四个值绑死：`.tab` 高度、`strip` 高度、`::-webkit-scrollbar` 高度、`.tab-insert` 的 top/bottom。已写进 `ARCHITECTURE.md`。

### 测试

`tests/regressions.test.ts` 的 B54 用例整体改写为 **B55 契约**（旧断言与新样式互斥，不能并存）：
药丸高度 ≤22 / `border: none` / `border-radius: 4px` / 不再是 `6px 6px 0 0` / color-mix 写法 /
`.tab-active` 含 `var(--tab-bg-active)` 且**不含** `border` / 两套主题都有三档变量 /
`tab-flash` 结束态是 `var(--tab-bg-active)` 且**不含** `var(--bg))`；
加几何断言 **`stripH - tabH === 滚动条高度 × 2`**（把「4 段绑死」这个不变量变成会失败的测试）。
结果 **299 vitest + 22 cargo 全绿**，`tauri build` 出 exe + NSIS（5,807,456 B）。

## B56 标签不再收缩：宽度跟内容走，放不下就滚动

用户反馈：「标签变多后，不要缩小标签宽度（会使得内容文本被裁剪，出现…）」。

### 根因

两处叠加，缺一不会出「…」：

1. `.tab { flex: 0 1 auto }` —— B53 做的「先收缩再滚动」（模仿 VS Code `tabSizing: fit`），
   标签一多就被 `flex-shrink` 压窄；
2. `.tab-name { overflow: hidden; text-overflow: ellipsis; min-width: 0 }` —— 名字负责吸收
   收缩量，于是被裁成「…」。

外加 `.tab { max-width: 200px }`：**就算标签不多**，超过 200px 的长文件名也会被截断。

### 改法（`src/styles/global.css`）

- `.tab`：`flex: 0 1 auto` → **`flex: 0 0 auto`**；**删掉 `max-width: 200px`**
  （对应 VS Code 的 `tabSizing: fixed`：不收缩、放不下就滚动）。`min-width: 60px` 保留，
  它只是最小宽度下限，不会造成裁剪。
- `.tab-name`：删掉 `overflow: hidden` / `text-overflow: ellipsis` / `min-width: 0`，
  `flex: 1 1 auto` → **`flex: 1 0 auto`**（仍吸收 `min-width` 带来的松弛，让 ●/× 贴右缘，
  但**禁止收缩**）。文件名从此整段显示。

💡 **几何不变量没受影响**：标签高度仍是 20px、标签栏仍是 28px = 4+20+4，只有**横向排布**
从「可压缩」变成「自然宽度」。所以 B55 那套高度测试原样通过。

### 测试

`tests/regressions.test.ts` 里 B53 的「先收缩再滚动」用例**整体改写为 B56 契约**
（新旧行为互斥，不能并存）：断言有 `flex: 0 0 auto`、**没有** `flex: 0 1 auto`、
**没有** `max-width`、`.tab-name` 是 `flex: 1 0 auto` 且**不含** `text-overflow: ellipsis`
与 `overflow: hidden`。

⚠️ **踩了自己的坑**：第一版断言直接失败 —— 因为我在 `.tab` 的注释里写了
「（flex: 0 1 auto + 收缩下限）」来记录旧值，而 `not.toMatch(/flex:\s*0 1 auto/)`
把**注释**也匹配了。修法：新增 `cssDecls()` 辅助函数**先剥掉 CSS 注释再断言**。
这个坑对以后同样适用 —— 注释里写旧值是好习惯，但静态断言要先剥注释。

结果 **299 vitest 全绿**。

⚠️ 行为影响：不收缩后**更早进入溢出**，所以横向滚动会比以前更常出现（这是预期，不是 bug）。

## B57 标签高度 / 关闭按钮 / 文件类型图标 全面对齐 VS Code

用户要求：「tab 标签高度和关闭按钮也参考下 vscode，vscode 标签上还有图标，都参考下」。
开工前用 AskUserQuestion 确认了两个设计选择，用户都选了推荐档：

- **高度**：24px 药丸 / 32px 标签栏（VS Code Modern UI「常规档」，而非 compact 的 20/28）；
- **图标**：**家族矢量字形 + 家族配色**（不用首字母徽标，也不用统一文档图标）。

### 依据（读的是 `docs/vscode-reference/` 里的上游源码，不是二手文章）

- `editorTabsControl.ts`：`EDITOR_TAB_HEIGHT = { normal: 35, compact: 22, modernUI: 32, modernUICompact: 28 }`。
  源码注释写得最直白：`modernUICompact: 28 // 20px tab + 4px top + 4px bottom padding
  // (20px = minimum to fit 16px icon + 2px padding)` ——
  **20px 只是「刚够放 16px 图标」的下限**，要给图标留呼吸就得用 24px 常规档。
- `tabs.css`：`--editor-group-tab-height: 24px`；`border-radius: small`；`padding: 0 size80 0 size60`；
  `.tab.has-icon` 时左内边距 8px→6px（图标自撑留白）。
- 关闭按钮：绝对定位覆盖层 `width: 24px`、`font-size: 16px`、`color: inherit`；
  显隐用 **`opacity`（0→1）** 而不是 `display`，条件 = `:hover` / `.active` / `.dirty` / `:focus-within`；
  非活动编辑器组整体 `opacity: 0.5`。

### 改了什么

**`src/styles/global.css`**

- `.tab`：高度 `20px → 24px`；padding `0 8px 0 6px → 0 4px 0 6px`（左 6px 对齐 VS Code size60，

## B58 应用级 tooltip 自绘层（取代原生 `title`，对齐 VS Code hover）

用户原话：「优化 tooltips 样式，可参考 vscode 源码」。
核心判断：**原生 `title` 不是「轻量提示」，是「不可控提示」** —— 由操作系统绘制，
配色/字体/圆角**跟不了应用主题**，加不了键帽与第二行小字，延迟由 OS 定（约 1s）。
深色界面里会突兀地弹出一个浅色系统气泡。所以整层换成自绘。

### 实现要点

- **`src/shell/tooltip.ts`**：单例 `.tooltip` 层 + `data-tip` 系列属性；**事件委托**
  （`document` 上 `mouseover/mouseout/focusin/focusout/mousedown`，`window` 上
  `scroll/resize/blur` + `Esc`）—— 标签栏/查找结果/大纲都是整块重绘的，逐个挂钩子要么漏、
  要么得在每次重绘后重挂。
- **定位抽成纯函数 `computeTipGeometry()`**：垂直越界翻面、水平夹进视口、
  caret 默认居中于框/中心点跑出目标横向范围则对准目标中心/最后夹进框内。
  抽出来的**唯一理由是「能测」**（jsdom 无布局，rect 恒 0，只能喂数字）。
- **秒开规则**（`groupId`）：容器标 `data-tip-group`（toolbar / menubar / statusbar / tabstrip …），
  同组内已有提示显示时下一个**秒开且不加淡入类**，顺着工具栏滑过去提示跟手、不闪。
- **两处有意偏离 VS Code**（写在文档注释里，防止后人「修回原样」）：
  ① `max-width: 420px`（VS Code 700px，那是给树视图长文本留的）；
  ② 提示层 `pointer-events: none` —— **否则鼠标从目标滑到提示上会让目标的 `:hover` 断掉、
  提示闪烁**；代价是提示文字不可选中（不需要）。

### 两个坑（都在代码注释里标了）

1. **`[hidden]` 必须显式 `display: none`**：`.tooltip` 与 `.tooltip-key` 都是 `display: flex`，
   会盖掉浏览器对 hidden 属性默认的 `display: none`（**和 B30 查找栏一模一样的坑**），
   否则没有快捷键 / 没有补充说明的提示会多出一块空白。
2. **`setTip` 顺带补 `aria-label`**：原生 `title` 同时是图标的**可访问名**，换成 `data-tip`
   后图标按钮会「失名」；只对**自身无文本、且没有显式 aria-label** 的元素补，不覆盖调用方。

### 接线（10 个模块的 `title` 全部迁走）

`index.html`（顶栏按钮改 `data-tip`，容器加 `data-tip-group`）、`menubar` / `menu` /
`tabstrip` / `splitview` / `toc` / `commandpalette` / `keymapdialog` / `findbar` / `main`。
`initTooltips()` 在 `bootstrap` 里**早于任何控件创建**装配。
唯一保留原生提示的是 `keymapdialog.ts` 的 `<option>`（`opt.title`）——
**原生下拉弹层覆盖在自绘层之上，自绘 tooltip 到不了那里**。
