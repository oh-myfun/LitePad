## WebView2Loader.dll 依赖的真正根因（重要，纠正此前误判）

### 结论
exe 是否依赖 `WebView2Loader.dll`，**取决于 Rust 工具链是 MSVC 还是 GNU**，与打包配置无关。

`webview2-com-sys-0.38.2/src/lib.rs:15-22` 的链接声明按 `target_env` 二选一：

```rust
#[cfg_attr(target_env = "msvc",  link(name = "WebView2LoaderStatic", kind = "static"))]
#[cfg_attr(not(target_env = "msvc"), link(name = "WebView2Loader.dll"))]
```

- **MSVC** → 静态链接 `WebView2LoaderStatic.lib`，loader 编进 exe → **单 exe 可跑，不需要 dll**（这就是 InkNote 的形态）
- **GNU(MinGW)** → 动态链接 `WebView2Loader.dll` → **exe 旁边必须有这个 dll**

LitePad 的 `rust-toolchain.toml` 锁 `stable-x86_64-pc-windows-gnu`（因无 MSVC link.exe），所以才会硬依赖 dll。

### 关键实证（推翻"不打包也能跑"的假设）
1. `pefile` 解析 `target/release/litepad.exe` 导入表：确认有 `WebView2Loader.dll`，符号为
   `CreateCoreWebView2EnvironmentWithOptions` / `GetAvailableCoreWebView2BrowserVersionString`（**加载期静态导入**）。
2. 7z 解开 `LitePad_0.11.0_x64-setup.exe`：payload 只有 `litepad.exe`，**没有** `WebView2Loader.dll`。
3. 直接启动（旁边无 dll）→ 退出码 `3221225781` = `0xC0000135` = **STATUS_DLL_NOT_FOUND**，**根本起不来**。
4. 对照实验：把 `webview2-com-sys` build 产物里的 `WebView2Loader.dll`（160320B）复制到 exe 旁 → **正常启动**。
   ⇒ 欠的就是这个 dll。**0.11.0 的 exe 与安装器当前是坏的，装完打不开。**

### 为什么"系统 WebView2 运行时会提供 loader"是错的
- 真实注册表 MACHINE/USER PATH 里**没有任何** WebView/Edge 条目（沙箱 PATH 不可信，须读注册表）。
- `C:\Program Files (x86)\Microsoft\EdgeWebView\...\153.0.4234.48\` 里**没有** `WebView2Loader.dll`；
  机器上 16 份该 dll 全是 Citrix/Huawei/Office/WSL 等应用自带，**都不在 PATH**。
- 现代 WebView2 Runtime 不再随附 loader dll，它只是开发期组件。

### 删掉 dropbridge.rs 也去不掉这个依赖
`Cargo.lock` 显示 `wry 0.55.1` / `tauri 2.11.5` / `tauri-runtime` / `tauri-runtime-wry`
**全都依赖 webview2-com**（不只是 litepad 自己）。所以 GNU 下任何 Tauri 应用都会静态导入该 dll；
想单 exe 只能切 MSVC 静态链接，或继续随包附带 dll。

  `C:\Program Files (x86)\Microsoft Visual Studio\2022\` 是**空目录** → **没有 MSVC link.exe**。

### 排查手法（可复用）
- 沙箱里 `objdump` 不可用 → 用 Python `pefile` 读导入表（最可靠）。
- 判断"缺哪个 dll"：直接 `subprocess.Popen` 起进程看退出码，`0xC0000135` = 缺 dll；
  再复制疑似 dll 到旁边重跑做对照，能起来即锁定元凶。
- 沙箱 PATH 是裁剪过的，**查系统 PATH 必须读注册表**
  （`HKLM\SYSTEM\CurrentControlSet\Control\Session Manager\Environment` 的 `Path`）。

## 新踩坑（MSVC 在本沙箱打包）

1. **Git 自带 coreutils 的 `link.exe` 会抢 MSVC 的 linker**：`which link.exe` → `/usr/bin/link.exe`。
   被抢时报错 `link: missing operand after '\xff\xfe'`（非 UTF-8 输出）。
2. **MSYS 路径转换会改写 `LIB` / `TMP`**：`LIB` 里 `;` 分隔的 Windows 路径、`TMP=E:\...` 传给原生
   link.exe 时会被改写 ⇒ `LNK1181 无法打开输入文件“kernel32.lib”`、
   `LNK1104 无法打开 C:\WINDOWS\lnk{...}.tmp`（非提权下写不进 C:\WINDOWS）。
3. **Windows SDK 版本要分开看**：`Windows Kits\10\bin` 是 `10.0.26100.0`，而 `Lib`/`Include` 是
   **`10.0.28000.0`** —— 按 bin 的版本拼 LIB 会找不到。
4. **沙箱限制**：Bash 里调用 `cmd.exe` 被安全策略直接拒绝（"bypasses all command validation"）；
   PowerShell 走 `vcvarsall` 会因内部调用 `reg.exe` 撞 Program Blacklist。
   ⇒ **`npx tauri build`（打 NSIS）在本沙箱做不了**，需用户在原生终端（x64 Native Tools Command
   Prompt 或已 vcvars 的 PowerShell）里执行。
5. `npx tauri build` 会因 tauri CLI 改了 feature 集而**重新编译 proc-macro**，比 `cargo build` 更容易
   撞上面 1/2 两条；用 `--config '{"build":{"beforeBuildCommand":""}}'` 可跳过前端重编
   （dist 没改动时不必要，且 vite 在沙箱里会挂死——node 进程涨到 1.6G 不出产物）。

## 收尾：用户报「127.0.0.1 拒绝连接」的真因与修复（同日补记）

**是我自己交付了错的产物**，且底下压着三层问题：

1. **第 3 步的 exe 是 dev 模式。** tauri 的判定是 `dev = !custom-protocol`
   （`tauri-2.11.5/build.rs:257` `let dev = !custom_protocol;`），而 `custom-protocol` 只在
   `tauri build` 时由 CLI 注入。于是 `cargo build --release` 出的
   `target/release/litepad.exe` 会去连 `build.devUrl`（`http://127.0.0.1:1420`），
   没有监听就直接显示这个错。**它只是编译校验产物，永远不可交付。**
2. **`dist/` 是空壳。** 更早那次 `npx tauri build` 的 vite 阶段被我 TaskStop 打断，
   `dist/` 只剩 `index.html`（8KB，`assets/` 434 个文件全丢）。此时 `tauri build`
   **照样 exit 0、日志全绿**，但产物 exe 3.76MB / NSIS 1.37MB（正常 8.1MB / 5.74MB），
   打开是一片空白 —— 「退出码 0 ≠ 生效」的又一例。
3. **`LIB` / `INCLUDE` / `TMP` 的覆盖才是链接失败根因，不是 MSVC 装错了。**
   实测：**默认 env** 下 `cargo build --release` 1m29s 成功、`tauri build` 1m56s 成功。
   前几轮所有 LNK1181 / LNK1104 都是我自己塞的 `LIB=…`（被 MSYS 改写）、`TMP=E:\…` 造成的。
   ⇒ **修正本文上面第 4、5 条的结论**：`tauri build` + NSIS 在**本沙箱能跑完**，
   **不要**再叠 vcvars / `cmd` / PowerShell 那套环境变量；直接
   `node node_modules/@tauri-apps/cli/tauri.js build --config '{"build":{"beforeBuildCommand":""}}'`。
