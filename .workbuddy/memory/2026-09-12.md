## B22 切换视图/点击内容区不得改动文件

用户反馈：只是切换 Markdown 预览⇄源码、或点击内容区，文件就被改了。
排查：CM6 的 `docChanged` **不等于"内容变了"**——编辑器被隐藏/恢复（切预览）、
重新测量、点击等场景都可能产生 docChanged 但前后文本完全一致的事务。
原 handleUpdate 只看 docChanged 就置脏，且**任何**更新（含纯选区变化）都 scheduleAutosave()
→ 一旦误置脏，1.5s 后自动保存就把磁盘文件重写了（EOL/编码归一化的写入肉眼可见）。
修复（src/main.ts）：
- handleUpdate 内加 `const textChanged = update.startState.doc.toString() !== update.state.doc.toString();`
  置脏与 scheduleAutosave() 都改为 `if (textChanged && !suppressDirty)`；
  会话保存（光标位置）仍按原逻辑。
- toggleViewMode() 用 suppressDirty 包住 applyPanelMode（切换视图绝不置脏）。
验证：写临时诊断脚本（jsdom bootstrap）跑过——切视图/点击在 jsdom 里不复现，
但"文本等价事务会置脏"是确定的漏洞，已用 tests/view-switch-noedit.test.ts 覆盖
（点击/选区/等价事务/切视图 均不置脏不写盘；真实编辑仍置脏并自动保存）。
**验证技巧**：把 textChanged 临时改成 true 跑一遍，确认测试会红（确有用）。
vitest 103 → 105。
