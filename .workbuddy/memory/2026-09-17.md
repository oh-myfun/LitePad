## B60（同日续）用户反馈三项：分隔条改细 / 落点回退浅蓝 / 对齐联动

用户原话：「分割条有点粗（参考 vscode 样式）。分屏预览颜色还是用之前的浅蓝色。
如果两条竖分割线位置一致时要能同时调整上下两根竖分割线（vscode 逻辑）。」

### ① 分隔条「粗」的根因是占位，不是线宽

排查：`.layout-sep` 是 `flex: 0 0 7px` 的**透明占位**，线本身只有 2px，但 7px 空档把两侧
内容撑开、露出祖先底色 —— 标签栏行上两侧是 `--bg-status`，中间这 7px 是 `--bg`，
色差就成了一条粗带。VS Code 的 sash 是 absolute 浮层、**完全不占位**（`sash.css`，
`--vscode-sash-size: 4px`），所以边界永远只是一条细线。

改法（`global.css` 的 `.layout-sep*` + `preview.css` 的 `.toc-resizer`，B28 同款）：
- 元素 `flex: 0 0 0` —— ⚠️ 只把**主轴**清零；交叉轴仍 `stretch` 成满长，所以
  `.layout-sep-h::before`（竖线）能写 `top:0;bottom:0`、`.layout-sep-v::before`（横线）
  能写 `left:0;right:0`。这点一开始差点想岔。
- 7px 命中区搬到 `::before`，向两侧各溢出 3.5px，压在相邻面板之上（B53 的宽命中区保留）。
- 视觉线 `::after`：静息 1px（VS Code `editorGroup.border` 就是 1px）→ 悬停/拖拽/联动 4px。
- 角手柄从「贴着 7px 带摆」（`top:0`/`left:0` + 7px）改成**骑在界线上**（`-4px` + 8px），
  否则分隔条主轴尺寸变 0 后手柄会整块偏到一侧。

### ② 落点回退浅蓝

`--drop-fill` 回到 accent @0.22（深 `#4c9ffe` / 浅 `#0969da`），`::after` 加回
`border: 2px solid var(--drop-fill)` + `border-radius: 4px`。描边压在填充上叠加成约
@0.39 → 「淡蓝底 + 略深蓝边」。**填充与描边同源**（都走 `--drop-fill`），改主题不会只改一半。
B59 从 `editordroptarget.css` 搬来的 70ms 位移 / 150ms opacity 过渡保留。

### ③ 对齐联动（linkedSash）

上游取证（本地 `docs/vscode-reference/`）：
- `gridview.ts:715-722` `trySet2x2`：两个 2 子节点分支 + 首子尺寸相等 → 互为 `linkedSash`。
- `sash.ts:342-347` 注释：linked sash「转发相同的 user interactions，移动完全一致。
  用于 2x2 网格」。
- `sash.ts:622-623` `_onDidReset` 也转发 → **双击复位要联动**。
- `sash.ts:629-648` `onMouseEnter/onMouseLeave` 也转发 → **悬停高亮要联动**。

实现（`splitview.ts`）：模块级 `sashRegistry`（只登记真实分隔条，角手柄不入册）
+ `centerOf()`（轴上中线，无布局回 null）+ `alignedSashesOf(handle, dir)`
（同向 + 中线差 ≤ `ALIGN_TOL=2`）。判定用**中线**而非 VS Code 的「尺寸相等」：
用户说的是「位置一致」，且中线判定能覆盖 3×2 等多行网格。
转发：mousedown 求一次 `links` → `onMove` 同步 `applyTarget` → `onUp` 各自 `commit`
→ `dblclick` 一并复位；`mouseenter/mouseleave` → 加/清 `.linked`（联动在按下前就可见）。
**角手柄 `links = []`**（双轴操作不参与）。

⚠️ `sashRegistry` 必须在 `renderSplitview` 里清空 —— 旧句柄已脱离文档，`centerOf` 恒为 0，
会误判成「全部对齐」。
