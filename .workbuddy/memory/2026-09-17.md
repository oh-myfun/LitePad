### 重要发现：O8「空面板自动收起」原本就已实现

方案里列的 O8 **不需要做**：`closeTabById`(855) / `moveTabToPanel`(1019) / `splitPanelWithTab`(1134)
三处早已在「源面板空了且非唯一」时调 `disposePanel`，而 `layout.ts` 的 `removePanel` +
`promoteSibling` 的 ratio 补偿就是「邻居吃满」。

### 坑

- ⚠️ **角手柄类名踩坑**：JS 生成 `layout-corner-start`（单类带连字符），而 CSS 选择器写的是
  `.layout-corner.start`（双类）—— 新测试立刻抓到。VS Code 用的是双类
  `.orthogonal-drag-handle.start/.end`，改成双类后一致。
- ⚠️ `body.layout-dragging` 是**三处共用**（分屏 / 大纲 `toc.ts` / 查找栏 `findbar.ts`），
  故**新增方向修饰类**而不是改基础类，避免横向拖拽（大纲/查找栏）光标被带错。
- ⚠️ `tabstrip-drag.test.ts` 有**源码级静态断言**（`clearInsertIndicators();` 必须紧跟
  `const zone = zoneOf(`），改 `onTabDragMove` 时保持了该形状。
- ⚠️ `zoneOf` 同时被**文件拖入**复用（`main.ts` 的 `showFileDropPreview` / `fileDropTargetAt`）。

### 与 VS Code 的有意偏离（记录，防「修回原样」）

1. 边缘阈值维持 **28%**（VS Code 10%）—— LitePad 面板少、拖拽更需容错；
2. 浅色分隔线沿用 `#dcdfe3`（VS Code `#E7E7E7` 在 LitePad 更密的布局里几乎不可见）；
3. 角手柄统一 `nwse-resize` 光标，未按四角细分方向；
4. S4 **未做「降亮度」**（VS Code 缩放时并不压暗面板），改为「取消过渡」。

⚠️ **观感项需桌面环境确认**：S2 落点填充色（深色灰 / 浅色蓝）与 O7 角手柄手感。
