# 2026-09-10

## LiteMD 轻量文本编辑器 · 技术方案 v1.0

- 需求：替代 Notepad++ 的轻量编辑器，多标签 + Xshell 式自由分屏 + 完善 Markdown 渲染，主打轻量高性能美观。
- 选型结论：**Tauri 2 + Rust 后端 + CodeMirror 6 前端**（对比 Electron / egui / WinUI3 / Qt 后胜出）。
  - 关键理由：安装包 8–20MB、内存 80–150MB、启动 0.2–0.5s；复用 `@codemirror/legacy-modes` 补齐 80+ 语言；npm 的 markdown-it/shiki/katex/mermaid 生态直接可用。
- 架构：Rust 侧持有"数据真相"（文件 IO/原子写、encoding_rs 编码转换、行尾、并行 grep 搜索、notify 监听、会话持久化），前端只做渲染与交互；大数据走流式 channel。
- 分屏核心：二叉树布局模型 `Split{dir,ratio,a,b} | Leaf{tabs,active}`；边缘带拖拽=新建 split，中央=合并，关闭标签时树自动规约；序列化进 session.json。
- 大文件分级降级：<2MB 完整 / 2–20MB 精简 / 20–200MB 只读 mmap 虚拟滚动 / >200MB 拒绝。
- 里程碑 M0–M5，单人全职 8–13 周到 v1.0。
- 主要风险：WebView2 依赖、中文 IME 候选框定位（CM6 已知痛点）、编码误判、Markdown 大文档卡顿。
- 产出文件：`LiteMD-技术方案.md`（工作区根目录）。
- 待用户确认：仅 Windows 还是跨平台 / 是否立即搭 M0 脚手架 / 项目命名。

## M0 脚手架开发

- 用户确认：仅 Windows、M0 范围、MinGW 工具链（三问均已拍板）。
- 环境勘察：Rust 1.98 在但 `cargo` 不在 PATH（走 `~/.rustup/toolchains/stable-.../bin`）；
  **MSVC 生成工具缺失**（VS2022 目录为空）；MSYS2 MinGW gcc 16.1.0 完整可用；WebView2 已装。
- 决策：`.cargo/config.toml` 固定 `target = x86_64-pc-windows-gnu`，用 MSYS2 链接器，
  避开 6-8GB 的 VS 安装。构建需 `export PATH="/c/msys64/mingw64/bin:$HOME/.cargo/bin:$HOME/.rustup/toolchains/stable-x86_64-pc-windows-msvc/bin:$PATH"`（见 scripts/dev.sh）。
- **纠错**：只加 GNU target 不够——build script/proc-macro 必须编译到宿主平台，
  宿主仍是 msvc 就还是要 link.exe。正确做法是装整套 GNU 宿主工具链：
  `rustup toolchain install stable-x86_64-pc-windows-gnu --profile minimal`，
  并用项目根 `rust-toolchain.toml` 锁定 channel。`.cargo/config.toml` 已删除。
- 完成：Tauri2+Vite+TS 骨架、core/{codec,eol,atomic_write,doc}、commands、session、
  前端 shell/状态栏/主题/CM6、图标生成脚本、test-data 多编码样例、DESIGN.md/TASK.md。
- 关键实现要点见 DESIGN.md（内存 LF 归一化、编码识别顺序、不可逆保护前置检查）。
- 已知偏差：M0 限 20MB、仅 Markdown 有高亮、JS bundle 569KB 未分割（记入 TASK.md M1/M4）。
