## B69：热退出开着时，空的未命名文档也要能跨重启回来

### 用户反馈

> 开启热退出时，如果又空的新建文档，下次打开也要能恢复

即：Ctrl+N 新建、还没打字的空文档，关窗再开要原样回来。

### 根因：会话的包含条件把它整条漏掉了

B68 把入会话判据从「只收有 `path` 的」放宽成 `!!d.path || d.backedUp`。
但**空的新建文档两个都不占**：

- 没有 `path`（未命名）；
- **不脏** —— 没输入过内容就不会触发 `scheduleBackup`，于是连副本都没有，
  `backedUp` 恒为 false。

结果：它压根写不进 `session.json`，下次启动自然无从恢复 →「新建了还没打字」的标签凭空消失。

### 修法：靠 `docId` 认领（而不是面板/标签索引）

给会话标签加 `TabSession.docId`（Rust `doc_id: Option<u64>`，= `doc::Doc::id`）：

1. **写入方向**（`snapshotSession`）：判据放宽为
   `有 path || 有副本 || (热退出开 && 无 path && 不脏)`，并把 `docId: d.tabId` 写进标签。
2. **恢复方向**（`restoreSession`）：`identityOf` 增加 `#doc:<docId>` 分支；
   预取时「既无 `path` 又无 `backupId`」= 空文档，调 `newTab` 造一个空白文档，
   放进 `restoredCache`（新增 `kind: "empty"`），且**不置脏**。

⚠️ **为什么必须是 `docId` 而不是「面板索引 + 标签序号」**：同一个空文档可以被分屏成
两个实例，按索引取两次就会恢复成**两份互不相干的文档**，破坏同源多实例 ——
和 B68 里「`restore_backup` 每次都新建标签」是同一类坑。按文档身份去重才对。

⚠️ **判定必须带 `!d.dirty`**：只写「无路径就收」，会把「**脏、但备份失败**」的未命名文档
也收进去，恢复时按空文档处理 → 真的把用户打的字丢掉。那种情况只能走关窗确认框
（快照里没有它 → 恢复时也不会被当成空文档）。

- `tests/hot-exit-empty.test.ts`（新文件，**恢复方向**，3 条）：会话里两个空标签（只有

## B71（调研中）面板拖拽 + 其它 VS Code 实用特性

用户：「vscode 面板支持拖拽，可能还有其他实用特性，参考下给出改进方案」。
结论（**参考库取证**，待用户选范围后再动手）：

### 「面板支持拖拽」确有其事，且不是指分隔条

- `vs/workbench/browser/parts/editor/editorTabsControl.ts:455-463` `onGroupDragStart`——
  注释 `only if originating from tabs container`（`e.target === element`）：
  **拖标签栏的空白区域 = 拖整个编辑器组**（该组所有标签一起走）。
- `editorDropTarget.ts:152,163` `isDraggingGroup` —— 投放侧区分「拖的是组」还是「单个编辑器」。
- `editorDropTarget.ts:280-282` `copyGroup` / `moveGroup` —— 落到边缘分屏时整组搬/复制，
  不是「新建组再塞一个标签」。
- `editorDropTarget.ts:320` `closeEmptyGroups && sourceGroup.count === 1` → 直接 `moveGroup`
  （拖走最后一个标签 + 分屏落点 = 整组搬走）。

**LitePad 缺口**：`splitview.ts:115 beginTabDrag(tabId, e, tabEl)` 只能从**单个标签**起拖；
标签栏空白目前是**双击 = 新建标签**，没有「拖整组」入口。
（分屏拖拽本身 B59–B63 已对齐 VS Code，O1–O7 / S1–S5 全部 ✅，别重复提。）

### ① 整组拖拽影像：从「克隆整条标签栏」改成聚合药丸

`localize('draggedEditorGroup', "{0} (+{1})")` —— 只有**活动标签名 + 其余数量**，

### ② 卫星窗口打不开：WebView2 环境参数不一致（**根因，非猜测**）

状态栏那句「新窗口没能打开，标签保留在原窗口」来自 B71 ④ 的超时兜底 —— 说明
`open_satellite_window` 之后窗口**从没就绪**。逐层取证后锁定根因链：

1. Windows 的 WebView2 **按 user data 目录共享同一个环境**；Tauri 强制同一 app 下所有
   `windows` 用同一目录（`%LOCALAPPDATA%\<identifier>`，源码注释见
   `tauri/src/manager/webview.rs`「in `windows`, we need to force a data_directory」）。
2. MS Learn `CoreWebView2Environment`：**user data 目录相同时，若 Environment 的
   `CoreWebView2EnvironmentOptions` 不一致，WebView 创建失败**
   （`0x8007139F` `ERROR_INVALID_STATE`；见 WebView2Feedback#257）。
