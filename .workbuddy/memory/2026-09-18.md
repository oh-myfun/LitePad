## B69：热退出开着时，空的未命名文档也要能跨重启回来

### 用户反馈

> 开启热退出时，如果又空的新建文档，下次打开也要能恢复

即：Ctrl+N 新建、还没打字的空文档，关窗再开要原样回来。

### 根因：会话的包含条件把它整条漏掉了

B68 把入会话判据从「只收有 `path` 的」放宽成 `!!d.path || d.backedUp`。
但**空的新建文档两个都不占**：

- 没有 `path`（未命名）；
- **不脏** —— 没输入过内容就不会触发 `scheduleBackup`，于是连副本都没有，
  `backedUp` 恒为 false。

结果：它压根写不进 `session.json`，下次启动自然无从恢复 →「新建了还没打字」的标签凭空消失。

### 修法：靠 `docId` 认领（而不是面板/标签索引）

给会话标签加 `TabSession.docId`（Rust `doc_id: Option<u64>`，= `doc::Doc::id`）：

1. **写入方向**（`snapshotSession`）：判据放宽为
   `有 path || 有副本 || (热退出开 && 无 path && 不脏)`，并把 `docId: d.tabId` 写进标签。
2. **恢复方向**（`restoreSession`）：`identityOf` 增加 `#doc:<docId>` 分支；
   预取时「既无 `path` 又无 `backupId`」= 空文档，调 `newTab` 造一个空白文档，
   放进 `restoredCache`（新增 `kind: "empty"`），且**不置脏**。

⚠️ **为什么必须是 `docId` 而不是「面板索引 + 标签序号」**：同一个空文档可以被分屏成
两个实例，按索引取两次就会恢复成**两份互不相干的文档**，破坏同源多实例 ——
和 B68 里「`restore_backup` 每次都新建标签」是同一类坑。按文档身份去重才对。

⚠️ **判定必须带 `!d.dirty`**：只写「无路径就收」，会把「**脏、但备份失败**」的未命名文档
也收进去，恢复时按空文档处理 → 真的把用户打的字丢掉。那种情况只能走关窗确认框
（快照里没有它 → 恢复时也不会被当成空文档）。

### 测试

  同时断言「没有内容可备份 → 不写副本」。
- `tests/hot-exit-empty.test.ts`（新文件，**恢复方向**，3 条）：会话里两个空标签（只有

## B70（排查中）tooltip 与 VS Code 的差异

用户反馈：「菜单栏上 vscode 不显示 tooltip，litepad 显示 tooltip 会和菜单重叠，类似的差异
可能还有」。排查结论（**已用参考库源码取证**，待用户选方案后再动手）：

### 取证（关键：参考库里有菜单/菜单栏源码，别靠记忆下结论）

- `docs/vscode-reference/src/vs/base/browser/ui/menu/menubar.ts` —— 全文 **0 次**出现
  `hover`，菜单栏部件**根本不注册悬停提示**。
- 同目录 `menu.ts` —— 只有 CSS 的 `:hover` 配色与滚动条色，没有任何提示注册，
  菜单项也**不弹提示**（连 `title` 属性都不设）。
- `platform/hover/browser/hoverService.ts` —— 文档级 `MOUSE_DOWN` 会 `_hideHover…`
  （本项目 `mousedown → hideTip()` 已对齐 ✅）；`isMouseDown` 守卫**只加在 `onFocus`**
  （第 678 行），`MOUSE_OVER` 分支**没有**按下守卫 →
  ⚠️ 我一开始以为「拖拽时弹提示」是差异，**查证后不是**，VS Code 同样会弹。别改。

### 差异清单

| 位置 | LitePad | VS Code | 判定 |
|---|---|---|---|
| 菜单栏按钮 | `menubar.ts:170` 弹「文件菜单 + Alt+F」 | **无** | 应删 |
| 菜单打开时 | 提示层 z-index **2000** > 菜单 **1000**，仍会弹并盖住菜单 | 不适用 | 应加抑制 |
| 弹出菜单项（带 `title`） | `menu.ts:228` 弹提示 | **无** | 待定（信息有用） |
| 工具栏 / 状态栏 / 标签 | 有（键帽、500ms、同组秒开） | 有 | 已对齐 ✅ |
| 大纲项 / 命令面板行 / 快捷键对话框 / 分隔条 / 标签关闭按钮 | 有 | 无 | 可选收紧 |

### 重叠的直接原因（两条叠加）

1. `.tooltip` 的 z-index 2000 是**刻意**高于菜单 1000 的，注释原话「菜单项也要能弹提示」。
2. 弹出菜单**没有遮罩**（`menu.ts` 只在外部 `pointerdown` 时关闭），所以菜单开着时
   鼠标划过工具栏/状态栏照样触发 `mouseover` → 提示浮到菜单之上。
   菜单栏那条尤其糟：提示默认 `placement: bottom`，正对着下拉菜单展开的位置。

## B71（调研中）面板拖拽 + 其它 VS Code 实用特性

用户：「vscode 面板支持拖拽，可能还有其他实用特性，参考下给出改进方案」。
结论（**参考库取证**，待用户选范围后再动手）：

### 「面板支持拖拽」确有其事，且不是指分隔条

- `vs/workbench/browser/parts/editor/editorTabsControl.ts:455-463` `onGroupDragStart`——
  注释 `only if originating from tabs container`（`e.target === element`）：
  **拖标签栏的空白区域 = 拖整个编辑器组**（该组所有标签一起走）。
- `editorDropTarget.ts:152,163` `isDraggingGroup` —— 投放侧区分「拖的是组」还是「单个编辑器」。
- `editorDropTarget.ts:280-282` `copyGroup` / `moveGroup` —— 落到边缘分屏时整组搬/复制，
  不是「新建组再塞一个标签」。
- `editorDropTarget.ts:320` `closeEmptyGroups && sourceGroup.count === 1` → 直接 `moveGroup`
  （拖走最后一个标签 + 分屏落点 = 整组搬走）。

**LitePad 缺口**：`splitview.ts:115 beginTabDrag(tabId, e, tabEl)` 只能从**单个标签**起拖；
标签栏空白目前是**双击 = 新建标签**，没有「拖整组」入口。
（分屏拖拽本身 B59–B63 已对齐 VS Code，O1–O7 / S1–S5 全部 ✅，别重复提。）

### 其它候选（VS Code 有、LitePad 缺）

| 项 | VS Code | LitePad 现状 | 成本 |
|---|---|---|---|
| 拖标签栏空白 = 搬整面板 | 有 | 无 | 中 |
| 最大化 / 还原当前面板 | `Toggle Maximize Editor Group` | 无 `maximize` | 中 |
| 移动标签到相邻面板（键盘） | `Move Editor into Next/Prev Group` | 内部有 `moveTabToPanel`（main.ts:1032），**未暴露成命令** | 低 |
| 按序号切面板焦点 | Ctrl+1/2/3 | 无 | 低 |
| 布局全局均匀重排 | `Reset Editor Group Sizes` | 只有双击单条分隔条均分 | 低 |
| 标签右键补齐方向拆分 | Split Up/Down/Left/Right | 只有「复制到相邻面板」 | 低 |
| 拖标签出窗口 → 新窗口 | 有（`isNewWindowOperation`） | 单窗口（tauri.conf 只有 `main`） | 高 |

⚠️ **多窗口不建议**：状态归 Rust 且 `AppState.docs` 全局共享，开第二个窗口要重新设计
「哪个窗口拥有哪些标签 / 会话恢复归属」，对一个轻量编辑器不划算。

## B71 ④：多窗口 —— 用户选择「做完整多窗口」

用户从「暂不做 / 副窗口独占 / 完整多窗口」里选了**完整多窗口**：新窗口与主窗口共享文档状态，
标签可来回拖。已告知成本（里程碑级 + 沙箱内无法验证，需真机多轮确认）。

开工前要摸清的既有条件（已确认的起点）：
- 前端已 `import { getCurrentWebview } from "@tauri-apps/api/webview"` → **不用新增 IPC**
  就能判断自己是不是主窗口（label === "main"）。
- `src-tauri/capabilities/default.json` 的 `windows` 只有 `["main"]`，新窗口要么加 capability
  要么用通配；tauri.conf.json 目前只有一个 `main` 窗口。
- 同文档多实例的 change-set 同步已经存在（同窗口内跨面板），跨窗口同步要复用这条路径
  改成「Rust 广播 + 各窗口 apply」。
- 会话目前只有一份 `session.json`，多窗口必须解决归属；热退出/关窗确认同理。

设计取舍（待落地时逐条定）：
- 卫星窗口**不进会话**（v1）：退出时把它的文档并回主窗口会话，避免丢未保存内容。
- 「拖回主窗口」的落点定位在跨窗口场景下最难，可先做成「卫星窗口里右键/按钮回到主窗口」，
  拖拽回搬留到后面。
